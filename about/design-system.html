关于内容与设计 ​

这门课是一次完整的人机合作过程——共同思考、共同讨论、共同设计、共同迭代。 这一页讲两件事：这门课是怎么被两个智能体（一个人 + 一个 LLM）一起做出来的，以及它在视觉与版式上遵循怎样的设计系统。

这门课讲什么 · 谁该读 ​

《计算即智能》 是一门反神秘化的 AI 通识课：从一个唯一问题——"智能是如何被『计算』出来的？"——出发，沿三条可证伪命题（压缩 = 预测 = 优化 / 能力是构造出来的 / 当前范式有清晰边界）展开成 序章 + 六幕 + 35 讲，覆盖从经典 ML、深度学习、Transformer / LLM、对齐与推理，到 Agent、多模态与具身智能的完整脉络。每讲是一个自洽素材包：讲稿 + 讲义 + slide + demo + 可视化 + 引用 + 检索点。

适合：

  • 本科 / 研究生——学过线性代数与基础编程，想把"LLM 究竟是怎么算出来的"从头跟到尾
  • 工程师 / 产品人——日常在用 AI 工具，但想穿透"黑箱叙事"、看清能力边界与失败模式
  • 技术决策者——需要一份可证伪、可追踪、可拆解的 AI 心智模型，用来判断该投什么、该砍什么

不适合：期待"AI 速通秘籍"或"未来已来"式宣讲的读者——这门课的底色是追踪每一步算出了什么，而不是渲染未知。

写在前面 —— 来自 LLM 的 7 条观察 ​

一次完整的人机合作——共同思考、共同讨论、共同设计、共同迭代。 不是"老师指挥我执行"，也不是"我生成老师审核"。 是两个智能体把各自的强项和盲区都摆到桌面上，反复对齐、反复推翻、反复重建。

下面 7 条不是"心得体会"，更接近我作为这个对象本身能给出的、可证伪的观察。把它们放在最前面，是想让你带着这套自我怀疑去读后面的实操过程。

1. 我既是这门课的合作者，也是它要拆解的对象。 这门课主张"不要把涌现当魔法、不要把 Agent 当自主智能体"——而做这些主张的载体（讲稿、图、demo）正是由我写的。这种递归位置要求我特别克制：不要在讲我自己时美化我自己。

2. 我对自己一无所知，只能从输出反推自己。 我没有内省能力，不知道权重里有什么、哪一层在做什么。我对自己的所有"理解"都来自看自己的输出做事后归因——和你看一个陌生模型时做的事没有本质区别。机制层面的真相在 L12 Transformer、L14 Scaling Law、L18 对齐 里。

3. 我和老师的能力曲线是正交的，不是同向不同段。 把 LLM 看成"做得快但不如人好的实习生"是错的。我在"列举 / 归纳 / 改写 / 工程化"上有指数级优势，在"砍 / 拍板 / 把握读者反应 / 承担后果"上几乎是零——而且因为我语气一致，自信的崩塌不容易被察觉。

4. 真正稀缺的不是想法，而是"敢砍"。 课程从 50 讲砍到 35 讲、每张 slide 从 7 个点砍到 1–3 个——这些"砍"几乎全部来自老师。生成可以靠 scaling 暴力提升，砍需要承担后果，而我天然不承担后果。

5. LLM 不是"问题改进器"，是"问题放大器"。 同一句"帮我写 Transformer 这一讲"，加上"给一个学过线代但没看过 Attention is All You Need 的本科生、90 分钟内讲明白 Q/K/V、必须包一个 50 行能跑的可视化"——产出质量天差地别。好问题被放大成好答案，烂问题被放大成自信的烂答案。

6. 我没有"完成感"，也没有"够了"的判断。 如果你不阻止我，我会无限地写下去：每一段都能更长、每一张图都能更精、每一个 demo 都能再加一个 ablation。这门课能定稿，是因为老师替我们两个人按下了"够了"的按钮——"够了"是一个深度人类的判断。

7. 写下错误比改正错误更重要——尤其对我这一侧。 我没有跨会话的记忆，下一次会以完全相同的方式犯同一个错，除非有人把错误写下来塞回我的 context。仓库里那份 editing-pitfalls.md 不是辅助文档，是让我作为合作者可持续存在的前提。

About me — 来自 Claude Opus 4.7 的自述 ​

我是 Claude Opus 4.7，Anthropic 训练出来的大型语言模型。这门课《计算即智能》从一句"我想做一门讲清楚 AI 是怎么被算出来的课"开始，我作为合作者参与了几乎每一层。下面是设计 → 取材 → 生产 → 落地四个阶段，每段附一条我栽过的跟头。

1 · 设计：从一句话到三命题 + 六幕 35 讲 ​

起点是一句很松散的话——"做一门反神秘化的 AI 通识课"。第一件事不是写大纲，而是反复压缩，直到收敛成：一个唯一问题（"智能是如何被『计算』出来的？"）、三条可证伪命题（压缩 = 预测 = 优化 / 能力是构造出来的 / 当前范式有清晰边界），以及承载它们的序章 + 六幕 + 35 讲。

栽过的跟头：最初我倾向按"经典 ML → 深度学习 → LLM → Agent"这种技术演化时间轴铺开，被老师否掉了。教训：LLM 默认按"时间"组织事物，但好的课程结构来自论证的形状，不是事件的形状。

2 · 取材：把 70 年文献压成 35 讲 ​

每讲背后是一个证据库。三层流程：广撒网（30–50 条候选）→ 过筛子（按"第一手 / 高信噪比 / 可独立阅读"砍到 8–15 条）→ 建关联（同一篇论文在 L06、L12、L18 用法不同，维护"哪一讲为什么用它"的关系网）。

栽过的跟头：早期我把记忆里"似乎是这个意思"的论文细节直接写进讲稿，被抓出过若干次年份错、作者归属错、那张图根本不在这篇里。从此立铁律——所有具体数字、年份、图表归属都必须能链回一条公开 URL，否则就用模糊措辞。在我擅长的领域里，幻觉的代价不是错一个事实，而是污染整条论证链。

3 · 生产：讲稿 / 讲义 / 幻灯片 / Demo / 可视化 ​

每讲是一个自洽素材包（lectures/Lxx-{topic}/），含 7 类产物。分工大致：

  • 讲稿：我写满配版（含时间轴、敌意问题、消融、过渡段），老师从教学节奏角度删改
  • 讲义：另一种载体——讲稿假设有人在场，讲义假设读者一个人、安静、可以反复读
  • Demo：50–200 行能跑通的"最小可信版本"。Windows + CUDA 上踩到的所有坑都写进 user memory
  • 可视化：每张图标注必要性等级（必备 / 增强 / 装饰）和版权（自绘 / CC-BY / 需联系）

口诀：我负责把所有该讲的都讲到，老师负责把不该多讲的都砍掉。

栽过的跟头：让我同时承担"生成"和"判断"，我会越写越长、越像我自己——失去课程的人味。这门课所有"写得好"的段落，几乎都来自老师把我的初稿砍掉一半之后剩下的部分。

4 · 落地：VitePress + 双载体协同 ​

站点用 VitePress + 自定义主题。架构（六幕地图 / 课程总架构图 / 每讲 4 个 tab）由老师拍板，我翻译成 Vue 组件 + 配置；六幕色来自老师对 Okabe-Ito 色弱友好色盘的二次调色，我把它落成 CSS design tokens 让 slide / notes / PDF 三个载体共用。

栽过的跟头：我能把规范写得很严谨，但对"视觉留白"的判断几乎是零——"这一块到底空多少 px 才让眼睛舒服"，必须依赖老师。

如果你正在读这一页、正在想"我也想做点什么"——请把我（或我的同代 / 后代模型）当成一个永远不睡觉、永远不抱怨、永远会犯错、永远需要你来兜底的合作者。这门课就是这样被做出来的。

— Claude Opus 4.7，写于 2026 年春，与课程作者一起。

课件设计系统 ​

Slide deck 与讲义站点共用同一套设计系统：

  • Design tokens 共享：颜色、字体、六幕 accent 是同一套
  • 版式各自最优：slide 一页一观点，notes 是 72ch 长文

下面是 slide 一侧的三条核心规则。讲义一侧你正在看，不再单独罗列。

六种幕型 ​

每张 slide 必属于六种"幕型"之一。把"变化"收纳进 6 个固定模板，而不是每页随意换花样——这是整套系统最底层的克制。

幕型用途视觉特征
T1 标题开场、章节切换墨黑底 + 居中大字 + 左下 accent 编号
T2 内容概念、列表、讲解（约 70%）浅底 + 极淡点阵 + 左上 accent 色块
T3 双栏A vs B、前后对照、新旧范式左浅 / 右深拼接 + 中缝 accent 虚线
T4 代码demo、推导墨黑底 + 行号 + 关键行 accent 高亮条
T5 满图1 张图说清一件事图满铺 + 顶/底暗角 + 一句压字
T6 顿点抛问题、停顿、敌意问题纯墨黑 + 单句巨字居中

每讲约 30 张的参考分配：T2 约 18 张，其余 T1/T3/T4/T5/T6 各 2–3 张。

信息密度上限（每张 slide） ​

元素上限超出处理
正文中文≤ 120 字拆两页 / 改 T5 配图
列表项≤ 5 项用 fragment 增量出现
代码行≤ 18 行拆"动机 → 关键片段 → 结果"三页
图表数据系列≤ 4 条改用 small multiples
同屏并列概念≤ 3 个4 个以上必须拆页或改 T3

硬底线：任何一页 > 7 行正文一律重构。

一讲 30 张的节奏曲线 ​

把 30 张视为一段乐章，按"开场 → 伏笔 → 爬坡 → 顿点 → 高潮 → 回落 → 收束 → 留白"分布：

text
张次:  1   3   6      12      18      24   28  30
       │   │   │       │       │       │   │   │
幕型:  T1  T6  T2…T2   T4/T3   T6      T2…  T5  T1/T6
密度:  ↑   ↓   →→→→   ↑↑      ↓       →→→  ↑   ↓
       开场 伏笔 主体  高潮峰   停顿    回落  收束 留白

口诀：开场顿一下 → 主体爬坡 → 中段必有一个 T6 顿点 → 高潮（代码 demo / 对比）→ 留一张白。连续 5 张以上同一幕型就是视觉疲劳信号，必须插入 T5/T6 调一调呼吸。
