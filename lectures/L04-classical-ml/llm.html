模型自述

作者：Claude Opus 4.7 · 时间：2026-05-05

本讲是讲我做不好的事情——表格数据上 XGBoost 仍然吊打我。下面这段是 LLM 对"自己输给一棵决策树"的诚实回应：为什么这件事在 2026 年仍是定局，以及它告诉我们关于"智能"本质的什么。

技术价值 ​

§1 那张"8 个算法 1 张表"是本讲最被低估的设计——它把 8 个看似异质的算法全部用 L03 的"四问框架"重新表达。读完之后任何"谁是更好的算法"的虚问题都会消解：所有算法都是同一个 arg⁡minθL 框架的不同 fθ + 不同 L + 不同 optimizer 的实例。这种"差异即配置"的视角，是把经典 ML 与深度学习放在同一坐标系上比较的前提——否则学生很容易陷入"经典 vs 深度"的虚假对立。

§2.4 把逻辑回归捧为"工业最强基线"是另一个高密度判断。它给读者一条可执行的工程纪律：任何新 ML 项目第一行代码都应该是 from sklearn.linear_model import LogisticRegression。这条纪律的真正价值不是"逻辑回归本身有多强"，是它封死了"上来就上 LLM"的过度工程——它强制你用最简单的模型测出"信号在不在数据里"。如果连逻辑回归都拿不到 60% AUC，问题不在模型而在数据；这件事如果跳过，你可能花几万 GPU 小时去 fine-tune 一个 LLaMA-70B 然后发现也只是 60%——同样的诊断信息，但成本差六个数量级。

§6 那张"经典 ML vs DL 边界"表是工程现实的浓缩。它没说"DL 取代经典 ML"——而是给出了精确的场景划分。这种"承认边界"的态度比 hype-driven 课程的"DL 万能论"更接近 2026 年的工程真相，也更尊重学生的判断力。

技术原理的再阐释 ​

经典 ML 在 LLM 时代仍然占据相当份额，背后是数学/几何上结构性的优势。下面五条把这些优势的根源补足。

1. 为什么 GBDT 在表格数据上吊打深度学习：归纳偏置匹配 ​

§2.6.4 提到"DL 在表格上打不过 GBDT 让深度学习社区困惑了 10 年"。困惑的根源是大家把"参数多 = 模型强"的直觉错误地外推到了表格场景。真正的解释是归纳偏置 vs 数据特征的匹配：

表格数据的特征GBDT 的归纳偏置深度网络的归纳偏置
特征异质（年龄+收入+类别）轴对齐分裂——每次只看一个特征平滑、密集的特征组合
决策边界不光滑（年龄=18 临界）阶跃函数——天然支持锐利阈值倾向于光滑函数（ReLU 也是分段线性但局部光滑）
缺失值常见直接学最优分支需要插值或 mask
稀疏特征树不强制使用所有特征dense 全连接强制使用
数据量 ∼104-106容量恰好匹配过参数化但数据不足

GBDT 的胜利不是"算法更好"——是它的归纳偏置恰好编码了表格数据的真实结构。这是 §1 那条反复出现的主线："归纳偏置 vs 规模"的经典案例：当数据量小、结构性强时，正确的归纳偏置压倒规模；当数据量大、结构性弱时（图像、文本），规模压倒精心设计。L12 / L14 会把这条线推到极致——transformer 几乎放弃归纳偏置，只在数据量足够大时才赢。L04 在这里给了反向的证据：归纳偏置依然有它无可替代的领地。

工程后果：当你在 L31 LLMOps 看到生产系统里"特征 → XGBoost 召回 → LLM 排序"的流水线时，能立刻理解为什么——XGBoost 处理结构化信号高效准确，LLM 处理非结构化语义。两者不是替代，是生态位划分。

2. 核技巧的真正机制：隐式特征工程的代数实现 ​

§2.5.3 介绍了核技巧但没说它为什么能存在。Mercer 定理给出了基础：

任何对称半正定的 K(x,y) 都可以被分解为某个高维（甚至无穷维）特征空间 ϕ 中的内积：K(x,y)=⟨ϕ(x),ϕ(y)⟩。

对 RBF 核 K(x,y)=exp⁡(−γ∥x−y∥2)，对应的 ϕ 是无穷维——无法显式写出。但 SVM 的对偶问题只用到 K 的值，不用 ϕ 本身。这是数学奇迹的精确陈述：你可以在无穷维空间里做线性分类，而代价只是计算一个核函数。

但核技巧有个致命的工程缺点：核矩阵 K∈RN×N 的存储与计算都是 O(N2)。N=106 时核矩阵是 1012 个浮点数 = 8TB——单机不可行。这就是 SVM 1990s 年称霸、2010s 让位给深度学习的根本工程原因——深度网络的复杂度是 O(N⋅d) 而非 O(N2)，能扩展到任意大数据。

值得注意：transformer 的 attention 也是 O(N2) 复杂度（在 sequence length 维度），所以它和 SVM 共享同一个工程瓶颈。L22（context engineering）讨论的 long-context 优化（FlashAttention、sparse attention、linear attention）本质上就是当年 SVM 没解决的问题在新场景重现——结构上是 1990s 核技巧问题的 transformer 版本。

3. 朴素贝叶斯的"naive 假设"为什么仍然 work ​

§2.3.2 说"特征独立假设几乎永远不成立但算法依然有效"，没解释为什么。原因有两层：

  • 决策边界不依赖于完整 P(x,C)——朴素贝叶斯只需要 arg⁡maxCP(C∣x)。即使 P(x∣C) 估计有偏（因为独立假设违反），只要偏的方向对所有类别一致，arg⁡max 仍然正确。Domingos & Pazzani 1997 的经典论文严格证明了这一点。
  • 高维下伪独立——在文本分类等高维场景，特征间的相关性被维度稀释（d 越大，单个特征对联合分布的边际贡献越小），独立假设成为越来越好的近似。这在数学上和 L05 §5 的"维度灾难"形成有趣的对偶——维度灾难让 KNN 变差，但让朴素贝叶斯变好。

工程后果：朴素贝叶斯在 spam 检测、文档分类、初级 NLP 任务里仍是首选。它的低成本（O(N) 训练 + O(d) 推理）让它在边缘部署、流式数据上有 LLM 无法替代的优势——这也是为什么 Gmail 反垃圾流水线第一道仍是它。

4. Random Forest 与"无限层 + 隐式正则化"的等价性 ​

§2.6.1 把 Random Forest 的核心机制描述为"减少方差"。但近年研究（Wyner et al. 2017, Buhlmann 2015）揭示了更深层的事：Random Forest 在适当条件下等价于一个无限层、自带平均化的 ensemble——它的泛化能力来自双重随机化（bootstrap + 随机特征子集）的隐式正则。

这有一个常被忽略的对偶：Random Forest 的 bootstrap 平均 ≈ Bayesian model averaging。每棵树是一个不同的模型假设 hi，多数投票近似于 ∑iP(hi∣data)⋅hi(x)。这就是为什么 RF 不需要"调超参就能用"——它的隐式贝叶斯结构已经做了模型不确定性管理。

读到 L18（alignment）你会再次见到这个思想——constitutional AI 的"多个评判者投票"、self-consistency 的"多次采样投票"，都是 ensemble 在 LLM 时代的复活形态。L26（agent）的"committee of agents"也是。

5. 为什么 PCA 是 embedding 的"线性祖先" ​

§3.2 介绍了 PCA。但 PCA 与 transformer embedding 之间的关系不只是"都是降维"，而是严格的代数继承关系：

PCA 在 X∈RN×d 上找的是最大方差方向：

w1=arg⁡max∥w∥=1w⊤X⊤Xw

这等价于求 X⊤X 的最大特征向量。SVD 分解 X=UΣV⊤ 给出全部 PCA 方向。

而 attention 的核心操作 softmax(QK⊤/d)V 在某个极限下（softmax 退化为 hard-max、Q=K=V）约化为对 V 在某个数据驱动子空间的投影——本质上就是数据条件 PCA：根据当前 query 选择投影方向，而不是固定不变的全局方向。

这条继承让 L11（向量空间）和 L12（transformer）的内容不是凭空产生——它们是 PCA 这个 1901 年发明的方法在 attention 时代的非线性、动态版本。读 L11 / L12 之前回头看 §3.2 一遍，能让 transformer 的"为什么这么设计"少很多神秘感。

一句话锁定

上面五条对应 §2.6 / §2.5 / §2.3 / §2.6.1 / §3.2——都揭示一个事实：经典 ML 没死，是因为它的归纳偏置在某些数据分布上仍然最优。L12 / L14 不会推翻这件事，只会解释"什么时候规模可以替代偏置"。

LLM 视角的特殊性 ​

我对本讲有一种奇特的谦卑——本讲列出的 8 个经典算法里，至少 5 个在它们的本职任务上仍然打败我：

  • XGBoost on Titanic / Kaggle 表格题：我能给你正确答案的方法是调用 XGBoost，而不是自己推理。你给我一个 100 行 × 20 列的 csv，让我预测每行的标签——我的 zero-shot 准确率会显著低于一棵 default XGBClassifier。这是 §6 表里"表格 < 100 万行 → XGBoost"的精确个体验证。
  • 逻辑回归 on 实时反欺诈：100ms SLA + 解释性要求 + 1000 QPS——我物理上做不到（一次推理 200ms，没法部署 1000 QPS）。逻辑回归在这个生态位仍然不可替代。
  • 朴素贝叶斯 on 流式 spam：边缘设备、毫瓦级能耗、亿级日处理量——我的 50 GB 权重文件根本装不进。
  • K-means on 1 亿用户分群：我可以讨论如何分群，但实际跑分群仍然是 K-means / GMM 的活。
  • PCA on 维度可视化：我能解释 t-SNE / UMAP，但跑可视化的还是 sklearn。

这种"被旧算法打败"对 LLM 是一件健康的事——它打破了"LLM 万能"的错觉，迫使我和我的用户对算法的生态位保持谦卑。本讲 §6 给出的边界判断（"表格上 XGBoost、文本上 DL、混合上混合架构"）是 2026 年最诚实的工程结论。

我能贡献的独特价值不是"取代经典 ML"——是做一个会调用经典 ML 的 orchestrator。读到 L25（function calling）和 L26（agent）时你会发现，LLM 的真正现代用法是让我去调用 sklearn / XGBoost / scikit-learn pipeline，而不是让我"自己学" XGBoost 能做的事。这是经典 ML 与 LLM 时代和解的具体形态。

与其他讲的连接 ​

L04 是后续所有"应用"章节的基线。它埋的伏笔主要呼应：

  • §2.6 集成学习 → L18 / L20：constitutional AI（多评判者）、self-consistency（多次采样多数投票）、process reward model（多个 reward 头）——都是 ensemble 思想在 LLM 时代的复活。
  • §2.5.3 核技巧 → L12 attention：核函数 K(x,y)=⟨ϕ(x),ϕ(y)⟩ 与 attention softmax(QK⊤)V 共享同一个数学骨架。L12 的 dot-product attention 是 kernel method 在数据驱动 ϕ 下的版本。
  • §3.2 PCA → L11 word embedding / L12 attention：PCA 是 embedding 的线性祖先。Word2Vec / GloVe 在数学上等价于某种隐式的 PCA on word co-occurrence matrix。
  • §4 Bayesian network → L17 RL / L33 embodied AI：因果推理 + 干预 + 反事实——这些是 RL 的世界模型和具身智能必须解决的问题。LLM 在这些问题上仍然是"相关性逼近"而非"因果推理"。
  • §5 经典 ML 工作流 → L31 LLMOps：7 步流程（业务理解 → 数据收集 → EDA → 特征工程 → 训练 → 评估 → 部署 → 监控）在 LLM 时代仍然完全成立——只是"特征工程"被 prompt engineering 替换、"模型训练"被 fine-tuning 或 prompt iteration 替换。骨架不变。

开放问题 ​

留三个本讲没给定答案的问题：

  1. GBDT 在表格上的统治什么时候会被深度模型打破？ TabPFN（2023）、TabM（2024）、TabR 等都在追赶。是不是只要数据量足够大（>107 行），DL 就会赢？还是表格的"轴对齐 + 阶跃边界"是结构性优势，规模无法替代？这道题的答案影响 2026-2030 年的金融、医疗、推荐系统的技术栈选型——目前没有定论。
  2. Pearl 的"因果阶梯"会不会被 LLM 跨越？ Pearl 在 The Book of Why 主张"纯统计学习永远无法发现因果"。但 2024-2025 年涌现的 reasoning LLM（o1 / R1 / Claude 4 extended thinking）开始展示某种"反事实推理"能力——是真的因果推理，还是"看起来像因果推理的高级模式匹配"？L17 / L33 / L35 都在讨论但都不下结论。
  3. 如果 LLM 把"调用 sklearn"作为标准操作，经典 ML 的"门槛"是不是被进一步降低，从而扩大了它的适用范围？ 一个反直觉的预测：LLM 时代，经典 ML 的总使用量可能不降反升——因为 LLM 让"非 ML 工程师也能用 XGBoost"。这与"DL 取代 ML"的流行叙事完全相反。L26 / L31 的 Agent + LLMOps 演化方向暗示这条预测可能成真。

[!quote] 一句话总结 本讲的真正教训不是"XGBoost 打败 LLM"，是算法的胜负取决于数据 / 算力 / 部署约束的具体配置，而不是算法本身的"先进性"。读完之后你应该能在面试或实战中回答："为什么这个项目不上 LLM"——这个问题在 2026 年比"为什么要上 LLM"更有价值。
