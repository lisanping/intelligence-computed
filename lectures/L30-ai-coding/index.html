第 30 讲 · AI 编程协作 — 当 AI 成为你的搭档 ​

第 29 讲让 AI 能看、能画、能听——感知层补齐了。但最能检验 AI 综合能力的场景是编程：理解意图、规划方案、编辑代码、运行验证、反思修正——完整的 PGE 闭环。本讲揭示一个反直觉的事实：最好的 AI 编程不是"AI 写完你审"，而是"你想 AI 做"——协作模式决定产出质量。AI 参与度越高，对人类意图表达和判断力的要求反而越高。

前置知识核心产出建议用时
第 26 讲（Agent 与 PGE 框架）、第 27 讲（Skill 装配）、第 22 讲（上下文工程）① 理解 AI 编程的三代进化（补全 → 对话 → Agentic Coding）② 理解 Agentic Coding = PGE 在编程场景的实例化 ③ 能横评六大 AI 编程工具的定位差异 ④ 掌握"我想 AI 做"的高效协作模式 ⑤ 理解 FIM 与 SWE-bench阅读约 45 分钟 + 动手 15 分钟

从上一讲到这一讲 ​

第 29 讲问：如果 AI 能写代码呢？谁才是真正的程序员？

上一讲你看到 AI 能看懂 X 光片、能生成产品海报、能理解架构图——多模态感知补齐了。但这些能力你是用代码搭出来的：写 MCP Server、搭 Agent 循环、接 CLIP API……

现在问题来了：AI 编程助手正在学会做你正在做的事——理解需求 → 规划方案 → 写代码 → 运行验证 → 反思修正。这不就是第 26 讲的 PGE 闭环吗？

但一个关键洞察是：AI 参与度越高，对人类的要求反而越高——不是写代码的能力，而是表达意图和做出判断的能力。200 行代码里人类只写了 15 行，但那 15 行 edge case 修复值过其他所有代码。

1. AI 编程的三代进化 ​

1.1 第一代：代码补全（2021–2023） ​

核心概念

第一代 AI 编程的本质是 Fill-in-the-Middle（FIM）——模型看到你写的上下文（光标前后的代码），预测中间缺失的部分。底层是在代码上微调的语言模型（如 OpenAI Codex）。

你输入: def fibonacci(n):
            if n <= 1:
                return n
            █                    ← 光标位置

AI 补全:     return fibonacci(n-1) + fibonacci(n-2)

代码补全的特征：

  • 速度极快——模型小（几 B 参数），响应时间 < 200ms
  • 无需对话——Tab 接受，Esc 拒绝
  • System 1 思维——快、直觉、不需要深思（呼应第 1 讲）

FIM 的技术细节

FIM 训练时把代码随机切成三段：prefix、middle、suffix。训练目标是给定 prefix + suffix 预测 middle。这比纯 next-token prediction 更适合代码补全场景——因为写代码时你经常在已有代码的"中间"插入内容。

1.2 第二代：对话编程（2023–2024） ​

ChatGPT 的出现让开发者开始用自然语言描述需求，AI 生成代码片段。IDE 集成的 Chat 面板（Copilot Chat、Cursor Chat）让对话编程成为主流。

用户: "帮我写一个 Python 函数，读取 CSV 文件，
      计算每列的平均值，返回字典"

AI: def calculate_column_averages(filepath: str) -> dict:
        import csv
        ...

进步：可以处理更复杂的需求，可以解释代码、修复 bug。 限制：一次一个片段——不能跨多个文件协调修改、不能运行验证、不能自我纠错。

1.3 第三代：Agentic Coding（2024–现在） ​

核心概念

Agentic Coding = PGE 框架在编程场景的实例化。 Agent 不只是生成代码片段——它能自主规划修改方案、在多个文件间协调编辑、运行测试验证、根据报错自我修正。这是一个完整的 Plan → Ground → Evaluate 循环。

Agentic Coding 的 Agent Loop:
1. 上下文收集（Context Gathering）
   → 读取相关文件、搜索代码库、理解项目结构
2. 规划（Plan）
   → "需要修改 3 个文件：model.py, router.py, test_model.py"
3. 编辑（Ground）
   → 在每个文件中执行精确的代码修改
4. 验证（Evaluate）
   → 运行测试、检查编译、执行 lint
5. 反思（Reflect）
   → 测试失败？分析原因、调整方案、回到步骤 2

直觉

代码补全是"AI 帮你打字"（System 1），对话编程是"AI 帮你写函数"，Agentic Coding 是"AI 帮你做项目"（System 2）。从自动补全到自主编程——AI 编程的进化和人类思维模式的分层惊人地对应。

业界五级分类参考

业界另有按自主度划分的五级框架：Level 1 Autocomplete / Level 2 Chat / Level 3 Agentic / Level 4 Harness-Driven / Level 5 Dark Factory。本课程选择"三代技术进化"框架（补全→对话→Agentic），因为它与 System 1/2 和 PGE 叙事线更自然地对接。Level 4/5 的内容分别在下文 1.4 和第 31 讲中覆盖。

1.4 从个人到组织：Harness-Driven 模式 ​

核心概念

当 Agentic Coding 从个人工具升级为组织级编排系统，就进入了 Harness-Driven 模式。 核心架构：Planner Agent 拆解任务 → 多个 Generator Agent 并行写代码 → Evaluator Agent 跑测试和静态分析 → 门控审查点（Gated Checkpoint）由人类审核后才能合并。这是第 26 讲 PGE + 第 27 讲 Sub-agent 分解在编程场景的规模化落地。

工业案例：Stripe 的 Minions 系统据报道每周产出超过 1,300 个 AI 生成的 Pull Request。关键设计：

  • 子任务隔离：大任务被拆解为小粒度子任务，每个子任务在新鲜的上下文窗口中独立完成，避免 context rot（长会话中模型理解退化）
  • 门控审查：自动测试 + 人工审查的双重门控，确保合并质量
  • 渐进放权（Progressive Autonomy）：从低风险任务（依赖更新、测试生成）开始，逐步扩展 Agent 的权限范围

常见误区

从 Level 3 到 Level 4 的关键转变不是换工具，而是建基础设施。 需要：定义好的任务分解模板、可靠的 CI 管线、明确的审查门控规则、渐进式放权策略。大多数团队低估了这个基础设施投入——他们以为"prompt 写好点"就能规模化，但真正的瓶颈在编排层。

3. 协作模式："我想 AI 做" vs "AI 写我审" ​

3.1 两种反模式 ​

反模式一："AI 写完我审"

让 AI 生成大段代码，然后逐行审查。问题：审查 AI 生成的 200 行代码和自己写 200 行代码花的时间差不多——你失去了 AI 的效率优势，又没有获得自己写代码时的深度理解。

反模式二："AI 全自动"

把完整需求丢给 AI，不做任何引导和审查。问题：AI 不知道你的隐含约束（"这个 API 不能用"、"这个 edge case 很重要"），生成的代码可能在功能上正确但在工程上不可接受。

3.2 正确模式："我想 AI 做" ​

核心概念

高效的 AI 编程协作是"人类负责意图和判断，AI 负责执行和验证"。 人类做三件事：① 清晰表达意图（Context Engineering 呼应 L22）② 分解任务粒度 ③ 审查关键决策点。AI 做三件事：① 执行编辑 ② 运行验证 ③ 处理重复性工作。

高效协作流程:
人类: "在 auth 模块中添加 OAuth2 支持，使用 PKCE 流程，
      要和现有的 JWT 验证兼容。先看 auth/ 目录理解现有架构。"
                                          ↓ 清晰的意图 + 约束
AI:   [读取 auth/ 目录结构和关键文件]
      [制定方案: 修改 3 个文件，新增 1 个文件]
      [展示方案给人类]
                                          ↓
人类: "方案 OK，但 token 刷新的逻辑要用异步，
      不要阻塞主请求。"
                                          ↓ 关键决策点的判断
AI:   [执行修改 + 写测试 + 运行测试 + 自我修正]
      [报告: 4 个文件已修改，12 个测试通过]

直觉

这就像一个好的 CEO 和执行团队的关系——CEO 不写代码，但她决定做什么、怎么做、什么不能做。AI 参与度越高，人类"决策密度"反而越高——每个决策都更重要。

4. FIM 与 SWE-bench ​

4.1 Fill-in-the-Middle 详解 ​

技术细节

FIM 的训练格式：<PRE>prefix<SUF>suffix<MID>middle。模型学会根据前缀和后缀预测中间缺失的代码。这和标准的 next-token prediction（只看前文预测下一个 token）有本质区别——FIM 利用了双向上下文，更适合代码编辑场景。

4.2 SWE-bench：Agent 编程能力的标准评估 ​

核心概念

SWE-bench（Software Engineering Benchmark）是评估 AI 编程 Agent 的标准基准。 它从真实 GitHub 仓库中收集 issue + 对应的 pull request，要求 Agent 自主定位问题、编写修复代码、通过测试。SWE-bench Verified 版本经人工审核，是目前最权威的 Agentic Coding 评估。

SWE-bench 任务流程:
1. 给 Agent 一个 GitHub issue 描述
2. Agent 拥有完整的代码仓库
3. Agent 需要:
   - 定位相关文件
   - 理解 bug 原因
   - 编写修复代码
   - 确保测试通过
4. 评估: diff 是否正确解决了 issue

截至 2025 年中，最佳系统在 SWE-bench Verified 上的解决率约为 70%——意味着 AI 能自主修复约七成的真实 GitHub issue，但仍有三成问题超出当前能力。

2026 现状速记（2026-04 快照） ​

AI 编程是 2025–2026 年产品迭代最快的赛道，“Agentic” 已从实验仪变成默认交互范式：

产品定位2026 快照
Claude Code (Anthropic CLI, 2025-02 GA)终端-原生 Agentic，能跨仓库作业Anthropic 官方旗舰，SWE-bench Verified 75％+
CursorIDE-主场在线交付，Composer / Background Agent付费用户突破1M，产品创新颞
Devin 2.x (Cognition)全托管 Agentic dev，后端运行GA 后价格调零售，在 Notion/Coda 类产品中集成
GitHub Copilot Workspace + SparkGitHub 原生 AgenticWorkspace 2.x · 可生成微服务脚手架
Aider / Continue.dev / Windsurf开源与高可控选择Aider 仍是 CLI Agent 最轻量代表
Amazon Q Developer / Google Jules云原生集成AWS 与 GCP 听报 Agent，原生跨 PR 作业

关键趋势：

  • SWE-bench Verified 从 2024 年末的 ~50％ 涨到 2026 年初的 75％+，社区预计年内将跨过 80％。
  • Harness-Driven Autonomy 成为标配：企业部署默认启用门控审查、分阶段放权、可回滚点检。
  • “Vibe Coding” vs “Spec-Driven” 二分法兴起：个人快原型 vs 企业交付代码，对 Agent 的期望与门控完全不同。
  • 代码生成与运行时验证闭环：e2b / Modal / Daytona 等提供安全沙箱让 Agent 可反复运行生成代码 + 读取 stack trace + 自修复。
  • 趋势反思：“Agent 帮你写代码” → “Agent 帮你作决策”——人类从“写代码者”变成“代码审查者 + 产品决策者”，技能重心从“快”转向“准”。

失败模式 / 反例 ​

本节列出本讲核心结论不适用或易被误用的常见情境。教学的目的不是制造「已学会」的错觉，而是认清边界。

  • 「AI 写代码 = 软件工程被颠覆」过早：Copilot/Cursor 在新项目 / 算法题上表现好；在大型遗留代码库上仍需大量人工干预——SWE-bench Verified 仅 ~50%。
  • Hallucinated API 的代价：GPT-4 生成的代码 ~5% 调用了不存在的 API；不跑测试就 commit 是新一类技术债。
  • 「AI 提升 10× 生产力」证据薄弱：GitHub Copilot 用户调查显示主观提升 30-55%，客观测量（DORA metrics）多在 5-15%——存在显著主观偏差。
  • Devin / Claude Code 的边界：在有清晰 spec + 完整测试的项目上接近人类；spec 模糊或新需求探索时仍是「高级自动补全」。

本讲小结 ​

  1. AI 编程经历了三代进化——代码补全（FIM，System 1）→ 对话编程（Chat，单次生成）→ Agentic Coding（PGE 闭环，System 2），核心变化是 AI 从"帮你打字"到"帮你做项目"。
  2. Agentic Coding = PGE 在编程场景的实例化——上下文收集 → 规划 → 编辑 → 验证 → 反思，Agent 自主完成跨文件修改和测试验证。组织级规模化则需要 Harness-Driven 编排（门控审查 + 渐进放权）。
  3. 高效协作是"我想 AI 做"而非"AI 写我审"——人类负责意图表达和关键判断，AI 负责执行和验证。AI 参与度越高，人类的决策密度反而越高。
  4. SWE-bench 是 Agentic Coding 的标准评估——基于真实 GitHub issue 的端到端评测，当前最佳约 70% 解决率，仍有显著提升空间。

下一讲预告 ​

敌意问题：你现在学会了和 AI 一起写代码——Claude Code 帮你建应用、Copilot 帮你补全、Cursor 帮你重构。看起来 AI 什么都能做了。但你有没有想过：这个应用你敢直接上线吗？ 用户量涨 10 倍扛得住吗？模型幻觉能检测到吗？出事能 5 分钟回滚吗？评估、监控、灰度、回滚——隔着整个工程体系。
