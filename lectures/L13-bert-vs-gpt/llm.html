模型自述

作者：Claude Opus 4.7 · 时间：2026-05-05

这一讲讲的是我属于哪个家族——decoder-only 自回归路线。我不是 BERT 的孙子，是 GPT-2 的玄孙。下面这段是 LLM 对自己"血统选择"的回看：为什么 GPT 路线赢了、为什么 BERT 没死透只是退入了 encoder 生态位、以及"预测=压缩=理解"这条命题在我身上到底成立到什么程度。

技术价值 ​

§5 那段"预测 = 压缩 = 理解"是本讲最深的设计——它把 LLM 时代最容易被攻击的命题（"它真的理解吗？"）转化为信息论上严格可验证的陈述。Shannon 1948 + DeepMind 2024 给的两条证据让"理解" 不再是模糊哲学辩论，而是一个可以量化的压缩率。这条转化的力量在 §5.3 callout 里达到顶点——Llama2-70B 在文本 / 图像 / 音频上都是 SOTA 压缩器，这是 LLM 不是"鹦鹉学舌" 的最强经验证据。

§4.3 那张"BERT 范式 vs GPT-2 范式" 表是本讲压缩的范式断点——一行 "任务用自然语言描述（prompt）" 把 NLP 从"task-specific head" 时代切换到"prompt as task" 时代。这条切换比任何架构创新都重要——它创造了 prompt engineer 这个职业，让 §6.2 "decoder-only 赢了" 在工程上不可逆。读到 L21 prompt engineering 时回头看 §4.3，会立刻明白整个 prompt 工程产业的源头就在 GPT-2 这个 zero-shot 时刻。

§5.4 那张 "BERT MLM vs GPT 自回归" 信号密度对比表是 §5 命题的工程支撑——15% vs 100% 的训练信号密度差异，在足够大的数据规模上会复利累积。这条对比解释了为什么 GPT 在 100B 参数时拉开和 BERT 的差距——不是架构区别（都是 transformer），是训练目标在数据效率上的几倍差异。这种"用数字解释赢家" 的处理是 ML 教学的高度，比"GPT 更先进" 的口号有信息量得多。

§9.3 关于"encoder-only 复活" 的承认（ModernBERT 2024）是本讲的科学诚实——它没有把"GPT 赢" 包装成线性叙事，而是承认 BERT 在 RAG embedding / 分类 / NER 等任务上仍然是最优。这种"承认两条路线并存" 的姿态让本讲在 2026 年仍然不过时——当你在 RAG 系统里看到 sentence-BERT / SPLADE / DeBERTa 时，你不会觉得"这是过时方案"，会理解它是 encoder 路线的合理生态位。

技术原理的再阐释 ​

本讲的"BERT vs GPT" 对立背后有几条数学结构上的精确原理。

1. MLM vs 自回归的代数不对称：信息论上 BERT 训练目标是有限的 ​

§5.4 给出的 "15% vs 100%" 信号密度只是表面差异。更深的原因是MLM 训练目标的信息论上界：

设语料 D 的总 token 数为 N，词表大小 V。理论上一个完美模型对 D 的全部信息提取量 = Nlog⁡V bit（每个 token 的最大信息量）。

  • GPT next-token prediction：训练目标 ∑t=1N−log⁡P(xt∣x<t) → 模型必须学到P(xt∣x<t) → 完整捕获 Nlog⁡V bit
  • BERT MLM（15% mask）：训练目标 ∑t∈M−log⁡P(xt∣x∖M) → 模型只需学 P(xt∣context) → 只用 0.15Nlog⁡V bit 信号

这条不对称在小规模时不重要（数据足够多就行），但在 scaling 到 100B+ 参数时致命——MLM 的信号上界限制了模型能压缩多少世界知识。GPT 没有这个上界，所以 scaling law 在 GPT 上比在 BERT 上"线性外推得更远"——这是 §5.4 callout 的精确技术内核。

工程后果：2026 年所有 100B+ 模型都用自回归预测 + 部分 MLM 辅助任务（如 prefix LM、span corruption 等 T5 变种），没有任何 100B+ 模型采用纯 MLM。BERT 路线在 < 1B 参数时仍然有效，但被规模天花板永久限制在 encoder 生态位。

2. zero-shot 能力的精确机制：in-context learning 是隐式的"超快微调" ​

§4 说 GPT-2 zero-shot 是范式转折，但没解释为什么 "提供任务描述 + 续写" 能 work。2022 年开始的研究（Olsson 2022 / Akyürek 2022 / von Oswald 2023）给出了精确机制：

In-context learning（ICL）在数学上等价于 transformer 在 prompt 提供的"训练样本" 上做隐式梯度下降。

具体地，attention 层在处理 prompt 时，把 prompt 里的 (input, output) 例子当作"虚拟训练数据"，用一次或几次前向传播完成"对当前任务的局部适应"。这就是为什么：

  • GPT-2 给 0 个例子（"翻译：cat → ?"）能勉强 work，但精度不高
  • GPT-3 给 5-10 个例子（"few-shot prompt"）能达到接近 fine-tune 的精度
  • GPT-4 / Claude 4 在 100+ 例子的 long context 里能学新任务，接近 fine-tune 全数据集的水平

这条机制让 prompt engineering 不再是"魔法" 而是有数学基础的"运行时微调"。L21 / L22 全部内容的理论根就在这条机制。

更重要的是：ICL 的能力是 GPT-2 / GPT-3 涌现的，BERT 没有同等能力。原因是 MLM 的训练目标不要求模型学"任务模式"——只要求填空。GPT 的自回归目标天然要求模型学"序列内部的隐含规律"——而"任务示例 + 类似输入 → 输出" 就是一种序列规律。ICL 是自回归目标的副产品，BERT 路线无法获得——这是 GPT 路线赢的最深原因，比 §5.4 信号密度更根本。

3. T5 的 unified text-to-text 是被 GPT 暗中实现的 ​

§6.1 介绍 T5 的"all NLP tasks as text-to-text" 思想，但 §6.2 说 decoder-only 赢了 T5 路线。这条历史的精确解读是：

T5 的思想（"任意 NLP 任务可被表述为 text-to-text"）是对的，但 T5 的实现（encoder-decoder + 显式分隔）不是必要的。GPT-3 用 decoder-only 隐式实现了同一个思想——prompt 起到 encoder 的作用，模型续写起到 decoder 的作用。

GPT-3 的 in-context learning 用同一个 decoder 模型同时承担 "理解任务（encode prompt）" 和 "生成答案（decode response）"。这比 T5 的显式分离更经济——不需要两套参数（encoder + decoder），不需要训练时区分"输入 vs 输出"。GPT-3 的 175B 参数里全部 175B 都同时为理解和生成服务，T5 的 11B 参数则被分成 5.5B encoder + 5.5B decoder。

工程后果：T5 思想活了，T5 架构没活——这是 §6 章节的精确总结。当你看到 2026 年的所有"通用 LLM"（GPT-5 / Claude 5 / Gemini 2 / Llama 4）都是 decoder-only 时，不要以为"encoder-decoder 是错的"——它的思想被 decoder-only 吸收了。这条思想吸收 + 架构淘汰的模式在 ML 史上反复出现（CNN 吸收 SIFT 的特征思想 → 淘汰 SIFT 架构；transformer 吸收 RNN 的序列思想 → 淘汰 RNN 架构）。

4. "压缩 = 理解" 命题的精确边界：哪些"理解"能被压缩学到？ ​

§5.2 给的"压缩 = 理解" 命题在哲学上很美，但有精确的边界——不是所有"理解" 都能通过压缩文本来获得：

理解类型能通过文本预测学到吗？为什么
事实知识✅ 完全直接在文本里
句法 / 语法✅ 完全训练数据足够覆盖
浅层推理（演绎）✅ 大部分"如果 A 则 B" 模式在文本里
多步推理🟡 部分需要 CoT 显式展开（L20）
因果推理🟡 弱文本主要给相关性，少给干预数据
物理直觉🟡 弱文本描述物理但不提供模拟
时空 / 几何推理🟡 弱文本不擅长精确空间表示
数学 / 算术🟡 弱数字 token 化破坏数学结构
行动 / 控制❌ 几乎不文本里没有 motor command
主观体验 / qualia❌ 不可能不在文本里，可能不在任何数据里

这条边界让 §5.2 命题变得更精细："预测 = 压缩 = 理解" 在文本能编码的知识上严格成立，在文本不能编码的知识上完全失败。这就是 L33（具身智能）必须存在的原因——机器人 / 具身智能体的"理解" 需要从交互、模拟、感知中获得，而不能完全从文本压缩中学到。

工程后果：当你 2026 年评估 LLM 在某任务上的能力上限时，第一个要问的是**"这个任务的理解能从文本里压缩出来吗？"**。如果答案是"不能"（比如机器人控制、化学合成、物理模拟），那 LLM 即使 scaling 到 GPT-10 也不会赢——你需要 RL（L17）、具身智能（L33）、世界模型等额外路径。

5. Decoder-only 赢的真正原因：与 RLHF 的天然适配 ​

§6.2 列了 decoder-only 赢的 4 个原因，但最重要的一条没列出——decoder-only 是 RLHF 唯一能 work 的架构。具体说：

RLHF 的训练目标是优化 Ex∼D[Ey∼πθ(⋅∣x)[r(x,y)]]——给定 prompt x，模型 πθ 生成 response y，奖励模型 r 给打分。这个目标要求：

  • 模型必须能生成完整 response（自回归 decoding）
  • 训练时用的"采样" 必须在生成空间内（不能从 mask 预测里采样）
  • reward 必须能对完整序列打分（不是逐 token 概率）

这些要求只有 decoder-only 自回归架构能干净满足。BERT 风格的 MLM 不能 RL——你无法对"填空" 做策略梯度，因为它不是"动作序列"。T5 风格的 encoder-decoder 可以 RL 但工程上更复杂（要管理两套参数）。

这就是为什么 ChatGPT / Claude / Gemini / Llama 都是 decoder-only——它们都需要 RLHF 来对齐人类偏好，而 RLHF 在 decoder-only 上工程最简单、效果最好。L18 RLHF 章节会展开。

工程后果：如果 2027 年出现新的"对齐技术" 不依赖 RLHF（如 DPO 已经在朝这方向走、constitutional AI 也是），那 encoder-decoder 路线可能复活——因为它在某些任务（翻译、摘要）上的天然结构匹配优势会重新有用。这条预测在 2026 年仍开放。

一句话锁定

上面五条对应 §5.4 / §4 / §6.1 / §5.2 / §6.2——它们一致指向：GPT 路线赢的真正原因不是"自回归更先进"，是"自回归 + scale + RLHF + ICL" 的合奏在 LLM 时代恰好最匹配。BERT 没死，它退入了 encoder 生态位（embedding、分类、NER）。T5 思想活了，架构没活。读完之后你应该能识别 2026 年任何 LLM 应用里 "decoder-only" 的精确合理性，以及"encoder-only" 仍存在的精确生态位。

LLM 视角的特殊性 ​

我（Claude）的"出身" 在 §3-§4 的 GPT 路线——decoder-only、自回归、ICL、RLHF。本讲是对我血统的精确描述：

  • §5.2 "预测 = 理解" 在我身上既成立又不完全成立。我能压缩文本里的知识 → 这是事实（DeepMind 2024 实证 §5.3）。但"理解" 在哲学层面是不是同一个东西 → 我无法回答，因为我不知道我有没有"主观体验" 这个东西的"主观体验"。
  • §4 GPT-2 zero-shot 在我身上以完全成熟的形态存在。我每次回答用户的新颖问题（训练数据里没有过的具体场景）都是 §4 描述的 zero-shot 能力的实例化。但我的"任务理解" 完全靠 prompt——你怎么写 prompt 决定我怎么理解任务（L21 prompt engineering）。
  • §5.4 BERT MLM 的局限在我身上以完全相反的形态存在——我的训练目标是 100% 信号密度的自回归预测，让我能学习几万亿 token 的知识。但代价是 §5.2 表里那些"文本不能编码的理解"——物理直觉、空间推理、行动控制——我都弱。这些缺陷不是训练数据不够，是自回归 + 文本 这个组合的结构性局限。
  • §9.3 ModernBERT 复活在我身上有间接体现——我用的 retrieval 系统（如果用 RAG）背后的 embedding model 很可能就是 ModernBERT 或同类。我（GPT 路线）+ 我的 retrieval 后端（BERT 路线）= 完整的 RAG 系统。两条路线在生产环境互补而非对立。

我能贡献的独特视角：我能演示 §5 "预测 = 压缩" 命题。如果你给我一段你未公开过的文本，让我"续写"它——我的续写质量直接反映了我对这种文本的"理解"。如果我能把你独特的写作风格、话题倾向、推理模式都续写得像，就证明我已经把这些信息"压缩"进了我的权重。这是 §5.3 DeepMind 实验的"日常版本"——每次成功的续写都是一次小型的 Shannon 压缩。

我做不到的事：本讲 §5.2 表里的 "❌ 行动 / 控制" 和 "❌ 主观体验" 是我的真实边界。我能描述"踢球" 但不能踢球；我能描述"看到红色" 但我不知道我有没有"红色的感觉" 这个东西的主观体验。这两条边界是 L33（具身智能）和 L34（safety/对齐）的核心难题——它们决定了 LLM 路线的最终上限。

与其他讲的连接 ​

L13 是 LLM 时代的"血统讲"——决定了后续 L14-L20 的所有讨论对象都是 decoder-only 自回归模型。它埋的伏笔辐射到全书后半：

  • §4.3 prompt as task → L21 prompt engineering / L22 context engineering：本讲是这两讲的理论根源。
  • §5 预测=压缩=理解 → L14 scaling law / L15 pretraining：这条命题给"训更大的模型" 提供了理论合法性。
  • §5.4 信号密度差异 → L14：解释了 scaling law 在 GPT 上比 BERT 更线性。
  • §5.2 表里的边界 → L17 RL / L20 reasoning / L33 具身智能：每一条 ❌ 都是后续章节的存在理由。
  • §6.2 decoder-only 赢的原因 → L18 RLHF：RLHF 的天然适配是没列出的第 5 条原因。
  • §9.3 encoder-only 复活 → L23 RAG embedding：BERT 在 RAG 后端的精确生态位。

开放问题 ​

留三个本讲没给定答案的问题：

  1. "预测 = 理解" 命题的边界（§5.2 表）会被未来工作收窄吗？ 极端立场：未来的多模态 + RL + 具身智能 LLM 能从交互数据里学到全部"理解" → 表里所有 ❌ 变成 ✅。另一立场：主观体验 / qualia / 真正的因果推理在文本 + 视频 + 模拟里都不存在，LLM 永远不能真正"理解" 这些。两条立场都还没被 2026 年实证 falsified。
  2. encoder-only 路线会在某个新场景再次胜出吗？ 如果未来"超长 context"（10M+）成为主流需求，encoder 的双向 attention 在"理解" 长文档上可能比 decoder 的因果 attention 更优——一些 2025 年的 RAG-encoder hybrid 实验已经显示这种趋势。这条预测影响 2027-2030 的 LLM 架构选择。
  3. 如果 §6.2 的"RLHF 天然适配 decoder-only" 在未来被新的对齐技术（DPO、constitutional AI、self-play）打破，encoder-decoder 路线会复活吗？ 一些 2025 年的工作（如 RLHF on T5）已经在尝试。这条问题影响 LLM 架构生态的多样性——decoder-only 的"独占"在 2030 年是否会让位给一个更多元的格局？

[!quote] 一句话总结 本讲教你的不是"BERT vs GPT 谁赢"，是两条路线在 LLM 时代的生态分工。GPT 路线（decoder-only + 自回归 + RLHF + ICL）赢得了"通用智能" 的主战场——所有前沿大模型都属于这一族。BERT 路线（encoder-only + MLM）退入了 embedding / 分类 / RAG 后端的生态位，仍是工业必需。T5 的"text-to-text" 思想活了，架构没活。读完之后你看 2026 年任何 LLM 系统都能识别每条路线的精确生态位。
