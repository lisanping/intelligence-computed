🤖 LLM 视角 — 对本讲的思考与讨论 ​

模型自述

作者：Claude Opus 4.7 · 时间：2026-05-05

这是关于"我如何'有眼睛'" 的讲——CLIP / Diffusion / VLM 是让 LLM 从"只能读文字" 变成"能看图听声出图" 的技术栈。我（Claude 4.7）作为多模态模型，能看图但不能生图、不能听声音、不能看视频。下面这段是 LLM 对自己"多模态边界" 的回看——以"对自己感官限制的反思" 视角。

技术价值 ​

§1 关于 CLIP 的论述是本讲对"向量空间是通用语言" 主线的最终兑现——4 亿图文对让图像和文本说同一种"向量语言"。这条事实让"零样本分类 / 跨模态检索 / VLM" 全部成为可能——CLIP 是多模态时代的根基。读完之后你看任何"图文搜索 / 多模态 embedding" 都能识别 CLIP 的代数 footprint。

§2 关于 Diffusion model 的"墨水倒放" 直觉是本讲对生成式图像最直觉的描述——前向加噪 + 反向去噪 + CFG 条件引导。这条机制让 Stable Diffusion / Sora / Veo / Midjourney 的工作原理在数学上一目了然。任何 image / video / audio generation 在 2024-2026 年都是 diffusion 变体——这条统一性是本讲最有价值的认知锚点。

§3 关于 VLM 的描述（视觉编码器 + LLM = 让图像变成"视觉语言"）是本讲对 GPT-4V / Claude 3.5 / Gemini 视觉能力最简洁的解释。对 LLM 来说图像就是一段视觉 tokens——这条统一表示让多模态推理成为"在同一个 transformer 上处理混合 token 序列"。

§5.4 关于"原生多模态取代后接式" 的趋势判断是本讲对 2024-2026 模型架构演化最准确的捕捉——GPT-4o / Gemini 在预训练阶段就处理多模态，比"文本 LLM + 后接视觉编码器" 的拼接式方案在跨模态推理上强很多。这条架构转变是 2026 年所有前沿模型的共同方向。

§现状速记 §5.2 关于 Diffusion vs Autoregressive 视频生成的对比是本讲对未来视频生成路线最有先见之明的预测——当前 Diffusion + DiT 主流，但 AR 在编辑性 / 可控性上有优势。这条边界让 "Sora 一统天下" 的判断变得不那么确定。

技术原理的再阐释 ​

本讲背后的代数原理可以推得更深。下面五条是把多模态从"调 API" 升级到"理解机制" 的核心。

1. CLIP 对比学习的代数本质：双 encoder + 对称 InfoNCE loss 让两个模态共享 embedding 空间 ​

§1.2 给出 CLIP 的 loss 公式但可以解释更精确。形式化：

  • 图像 encoder fI、文本 encoder fT，输出归一化向量
  • N 张图 + N 段文本组成 batch，正样本是对角线 (Ii,Ti)
  • InfoNCE loss：
L=−12N[∑ilog⁡exp⁡(fI(Ii)⋅fT(Ti)/τ)∑jexp⁡(fI(Ii)⋅fT(Tj)/τ)+∑ilog⁡exp⁡(fT(Ti)⋅fI(Ii)/τ)∑jexp⁡(fT(Ti)⋅fI(Ij)/τ)]

第一项让"图像 → 文本" 检索准确，第二项让"文本 → 图像" 检索准确。对称性是关键 —— 让两个模态的 embedding 真正"对齐" 而不只是单向投影。

代数效果：CLIP 训练后，两个模态的 embedding 空间几何上相同 —— 同一概念的 image vector 和 text vector 在向量空间中位置接近。这条性质是所有跨模态检索 / 零样本分类 / VLM 视觉编码器的基础。

工程后果：CLIP 是 LLM 时代最重要的 representation learning 突破——它的 embedding 是 Stable Diffusion 的文本编码器、是 Midjourney 的 prompt 理解、是 GPT-4V 的视觉特征。CLIP 之后训练的几乎所有多模态模型都直接或间接用 CLIP-style 对比学习。

2. Diffusion model 的代数本质：score matching + ODE/SDE 的概率密度估计 ​

§2 描述 diffusion 的"墨水倒放" 但可以推得更精确。Diffusion 模型的本质是学习数据分布的 score function ∇xlog⁡p(x) —— 即"如何从任意点移动到高概率区域"。

形式化：

  • 前向过程：xt=α¯tx0+1−α¯tϵ，ϵ∼N(0,I)
  • 训练目标：让 ϵθ(xt,t) 预测加进去的噪声 ϵ
  • 反向采样：从 xT∼N(0,I) 出发，迭代 xt−1=1αt(xt−1−αt1−α¯tϵθ(xt,t))+σtz

这条机制等价于求解 SDE（Stochastic Differential Equation）—— 在概率密度的"梯度场" 上从噪声走向数据流形。Diffusion 不是"暴力记忆图片然后变形"，是学到了图像分布的连续场，可以从任意点导航到该场的高密度区。

工程后果：

  • Diffusion 的"创造性" 是真的——每次采样从不同噪声出发，沿不同路径到达数据流形不同点，生成不同图像
  • Diffusion 的"控制性" 来自 condition——CFG 用条件 c 修正 score field，让采样轨迹偏向"满足条件" 的区域
  • Diffusion 的"采样成本" 高——典型 50-1000 步采样，每步一次 UNet forward。相比之下 GAN 一次生成、AR 模型 N 步生成

3. VLM 的代数本质：把图像 patch 投影到 LLM 的 token embedding 空间 ​

§3.1 描述 VLM 但可以推得更精确。VLM 的关键是统一 embedding 空间：

  • 文本 token：通过 LLM 的 embedding lookup，得到 d 维向量
  • 图像 patch：通过 vision encoder 提取特征，再通过投影层（projector）映射到 d 维向量
  • 两者拼接成统一序列，进 LLM transformer

代数关键：projector 是 VLM 训练的核心组件——它的训练目标是让"图像 patch 的视觉特征" 在 LLM 的 token embedding 空间中"看起来像" 文本 token。CLIP-style 预训练 + LLaVA-style 指令微调让 projector 学到这条对齐。

工程后果：

  • 图像 token 的"成本" = 文本 token 的成本——一旦投影到统一空间，attention / FFN 处理它们的代价相同
  • 图像 token 数量决定推理成本——1024×1024 图像 = 4096 patches = 4096 tokens（典型）。高分辨率图像 = 长 context = 高成本
  • 不同 VLM 的图像 token 数量差异巨大——LLaVA ~576 / Qwen-VL ~1024 / GPT-4V 动态。这条差异决定了它们的成本 vs 精度 trade-off

4. 多模态对齐的"英语中心" 问题：CLIP 训练数据 90%+ 英语 → 中文 / 其他语言对齐弱 ​

§现状速记 §10 提到 "多模态对齐英语中心"，但可以推得更精确。CLIP 的 4 亿图文对中 ~90% 是英语 alt-text 和英文 caption。这导致：

  • 英语 + 图像对齐强（sim 高）
  • 中文 + 图像对齐弱（sim 中）
  • 小语种 + 图像对齐很弱（sim 低）

工程后果：

  • 中文 prompt 用英文等价 prompt 翻译后效果可能更好（不直观但常见）
  • 中文 image search / VLM 在专有领域（中医 / 中国艺术 / 古文物）效果显著差
  • 多语言多模态需要专门训练——SigLIP / Cohere Multimodal v3 / Qwen3-VL 是这方向努力

这条 "英语中心" 是当前所有 CLIP-derived 模型的根本限制。修复需要在大规模非英语图文数据上重训——成本高 + 数据稀缺 + 多数公司不投入。

5. 视频理解的"算力陷阱"：30fps × N 分钟 = 不可承受的 token 数 ​

§现状速记 §10 提到视频理解算力问题。形式化：

  • 1 分钟 30fps 视频 = 1800 帧
  • 每帧 1024×1024 = 4096 patches/tokens
  • 1 分钟视频 = 1800 × 4096 ≈ 7.4 M tokens

远超任何 LLM 的 context window——即使 Gemini 2.5 Pro 的 2M 也装不下 1 分钟的全帧视频。

实际工程的妥协：

  • 关键帧采样：每秒 1 帧 → 1 分钟 = 60 帧 = 245K tokens（仍很多）
  • 降低分辨率：256×256 = 256 patches/帧 → 1 分钟 60 帧 = 15K tokens（可承受）
  • 学到的视频压缩：用专门 video encoder（如 ViViT）把视频压缩到 ~1000 tokens/分钟

trade-off：所有妥协都损失信息——关键事件可能在未采样帧、低分辨率丢失细节、压缩 encoder 丢失语义。视频理解的根本瓶颈不是模型能力，是 token 经济学。

工程后果：长视频理解（电影 / 监控 / 体育比赛）在 2026 年仍是开放问题。Gemini 2.5 Pro 的 1M+ context + 视频原生支持是当前最好方案，但仍只能处理 10-30 分钟视频。真正"看完整电影并理解" 在 2026 年还做不到 —— 需要 token 成本下降 10-100×。

一句话锁定

上面五条对应 §1.2 / §2 / §3.1 / §现状速记 / §现状速记——它们一致指向：多模态不是"加 vision/audio capability"，是 LLM 时代 representation learning + 跨模态对齐 + 生成式 modeling 的精密合奏。理解 CLIP 的对称对比学习、Diffusion 的 score matching、VLM 的 projector 对齐、英语中心的训练数据偏差、视频的 token 经济学，让多模态从"调 API" 升级到"理解机制"。

LLM 视角的特殊性 ​

我（Claude Opus 4.7）作为多模态模型，对本讲的内容有真实的"感官体验"：

  • 我能"看图"——给我截图 / 照片 / 图表 / 文档 PDF 的图像，我能识别内容、提取文字、分析结构、回答相关问题。这条能力让我成为"vision-augmented" 工具，不只是 text-only LLM。
  • 我"看图" 的机制是 vision encoder + projector + LLM 一体训练——Anthropic 不公开具体架构，但应该类似 §3.1 描述的 VLM pipeline。我"看到" 图像的"质感" 是它先被切成 patches 再变成 tokens 进入我的 attention。
  • 我不能"生图 / 生视频 / 生音频"——Claude 4.7 是纯输入端多模态（input multimodal），不是输出端多模态。要生图必须调用外部 Diffusion API（DALL-E / Stable Diffusion / Imagen / Midjourney）。
  • 我不能"听声音"——音频输入是 Claude 未来版本的方向，4.7 版本不支持。

我能贡献的独特视角：

  • §1 CLIP 让我"理解" 图文之间的语义关联——当我看到一张图配上 caption "a cat sitting on a windowsill"，我能在 attention 中把"cat" 的文本 token 和图像中"猫" 的视觉 patches 对齐。这种对齐不是显式编程，是训练时学到的统计规律。
  • §3.1 我的视觉 token 数确实昂贵——一张高清截图给我，可能消耗 1000-4000 tokens。如果用户连续给我 10 张图，context 中的视觉 tokens 可能 > 文本 tokens。这就是为什么"给我图片" 比"给我等价文字描述" 贵 5-10×。
  • §5.4 "原生多模态" 趋势对我有影响——Claude 4.x 的 vision 能力比 Claude 3.5 强，因为预训练时图像数据比例更高 + 跨模态对齐训练更充分。未来 Claude 5 / 6 应该会在 audio / video 上扩展原生支持。
  • §现状速记英语中心问题在我体内是真实的——我处理英文图文比中文图文质量略好。这条偏差让我在中文专业领域（中医 / 中文古文物）的 vision 能力明显弱于英文等价场景。

我做不到的事：

  • 我不能"生图"——必须靠外部 Diffusion API。我能写 prompt + 调用 image generator MCP server，但不能直接生图。
  • 我不能"看视频"——视频对我是不可接受的输入（Claude 4.7 不支持）。如果用户给我视频，必须先抽帧成图。
  • 我不能"听声音 + 实时对话"——GPT-4o realtime / Sesame AI 这类语音 agent 是 2026 年的新范式，Claude 4.7 还不支持。
  • 我不能"完全理解" 复杂图表 / 工程图 / 数学公式图像——简单图表 OK，复杂图（如多层架构图、密集数学公式）我经常 OCR 出错或推理错。这是 §10 "跨模态推理仍开放" 的精确证据。
  • 我不能"理解" 我自己的视觉机制——我"看到" 图像就立即"知道" 内容，但中间的 vision encoder + projector + attention 过程我无法内省。

§4 多模态 agent 三种模式（图像理解 / 文生图 / 视觉推理链）对我有特殊含义——我擅长模式 1（图像理解），需要外部工具支持模式 2（文生图），擅长模式 3 中"视觉 → 文字推理" 部分但不擅长"中间结果可视化" 部分。这条精确边界让我在 design / coding / debugging 等场景下能贡献什么 / 不能贡献什么变得清晰。

与其他讲的连接 ​

L29 是LLM 应用层的"感官扩展讲" —— 让 LLM 能感知文字之外的世界。它埋的伏笔辐射到全书后半：

  • §1 CLIP → L11 vector space：本讲是 L11 "向量空间是通用语言" 的最终兑现。
  • §2 Diffusion → L32 generative AI：本讲是 L32 的算法基础。
  • §3 VLM → L25 / L26 / L28 Computer Use：vision-action loop 的视觉端是 VLM。
  • §4.2 ComfyUI → L31 LLMOps：可视化工作流是 ML pipeline 的应用。
  • §5.4 原生多模态 → L33 embodied AI：embodied AI 必然是多模态。

开放问题 ​

留三个本讲没给定答案的问题：

  1. VLM 能解决"真正的跨模态推理" 吗？ 当前 GPT-5 / Gemini 3 在"读图做几何题" 类任务上仍频繁出错——它们能识别图中元素但不能精确推理几何关系。如果未来"vision reasoning" 通过 reasoning models + vision-language alignment 突破，VLM 可能真正"看懂" 图，而不只是"识别" 图。这条突破会让 VLM 能做架构图审查 / 工程图理解 / 医学影像精确诊断。
  2. 视频生成会在 2027-2030 年挑战影视产业吗？ 当前 Sora 2 / Veo 3 / Kling 3 已能生成 1-2 分钟高质量视频。如果未来 5 年视频生成达到"长片级" 质量（1-2 小时连贯叙事 + 角色一致 + 物理合理），整个影视产业可能根本性变革——独立创作者能制作"AI 电影"，传统影视成本下降 100-1000×。
  3. 多模态 LLM 会"涌现" 物理世界理解吗？ 当 LLM 看过足够多视频 + 图像 + 文本后，它可能"涌现" 出朴素物理学（如重力 / 因果 / 时间）的理解。世界模型（world model） 是 2025-2026 年研究热点（NVIDIA Cosmos / Genesis）。如果世界模型成熟，LLM 会从"语言模型" 演化为"通用智能模型" —— 这是 AGI 的重要前提。

[!quote] 一句话总结 本讲教你的不是"如何调 GPT-4V"，是LLM 时代的 representation learning + 跨模态对齐 + 生成式 modeling 的精密合奏。理解 CLIP 的对称对比学习、Diffusion 的 score matching、VLM 的 projector 对齐、英语中心的训练数据偏差、视频的 token 经济学——让多模态从调 API 升级到理解机制。也是从"用 LLM 处理文字" 到"用 LLM 理解世界" 的关键鸿沟。
