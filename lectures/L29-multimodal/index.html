第 29 讲 · 多模态应用 — 当 AI 同时拥有眼睛和嘴巴 ​

从第 11 讲起我们知道"所有模态都是向量空间中的几何问题"——但那时向量空间里住的只有文字。

本讲把图像、语音、视频全部拉进同一个空间。多模态不是"分别处理每种模态再拼接"，而是找到统一的表示空间。向量空间再次成为 AI 理解世界的通用语言。

2024-2026 年是多模态从"实验室"到"产品"的转折——GPT-4o 实时语音对话、Gemini 视频理解、Sora 视频生成、Suno 音乐生成、ElevenLabs 语音克隆。这些都建立在 CLIP 的对比学习思想 + Diffusion 的去噪思想 + Transformer 的统一架构上。

前置知识核心产出建议用时
L11（向量空间）、L12（Transformer）、L23（Embedding）、L28（协议）① 理解 CLIP 对比学习如何将图文拉进同一向量空间 ② 掌握扩散模型（Diffusion Model）的"墨水倒放"直觉 ③ 理解 VLM 如何让 LLM "长出眼睛" ④ 掌握多模态 Agent 设计模式 ⑤ 动手体验 ComfyUI 工作流 ⑥ 看 2026 年多模态生态（GPT-4o / Gemini / Sora / Suno） ⑦ 理解 Diffusion vs AR 视频生成的路线之争 ⑧ 拿到 L32 (生成式 AI)、L33 (具身) 的伏笔阅读 ~75 分钟 + 动手 ~30 分钟

从上一讲到这一讲 ​

第 28 讲问：世界不是文本的——只活在文字里的 Agent 和看不见的人有什么区别？

上一讲你的 Agent 获得了完整的互操作能力：MCP 连接生态、A2A 跨 Agent 协作、Computer Use 兜底。但所有这些交互都建立在一个假设上——信息是文本形式的。

用户发了一张 X 光片说"帮我看看有没有问题"——Agent 看不懂。用户说"帮我生成一张产品海报"——Agent 画不了。你的协议栈完美，工具链完整，但 Agent 是盲的。

本讲要解决的问题：如何让 AI 同时理解文字、图像、语音和视频？ 答案不是给每种模态配一个专用模型再拼接结果——而是把所有模态映射到同一个向量空间中。第 11 讲的理论洞见，今天变成了工程现实。

[!abstract] PGE 视角（L26 框架的多模态版） 回到 L26 §1 PGE 框架：Plan（规划） → Ground（接地） → Evaluate（评估）。多模态对应的正是 Ground 这一步在物理世界的扩展：

PGE 步骤纯文本 Agent（L25–L28）多模态 Agent（本讲）
PlanLLM 用文本规划LLM 用文本规划（不变）
Ground通过 Function Calling / MCP 读 API 数据再加一层：通过 VLM 看图片、ASR 听语音、视频帧理解物理事件
EvaluateLLM 评判 / RM 打分LLM 评判 + 跨模态一致性检查（生成的图是否真满足文本要求）

换句话说：多模态把 Agent 的"感知通道"从 1 条（文本）扩到 4 条（文本 / 图像 / 语音 / 视频）。Plan 与 Evaluate 的核心机制不变，但 Ground 的输入空间变成了 4 维。这也是为什么 L33 具身智能 把"传感器输入"作为 Ground 的进一步泛化——多模态是从"屏幕"看世界，具身是从"传感器"看世界。

1. CLIP：对比学习把图文拉进同一空间 ​

1.1 从 ImageNet 分类到 CLIP ​

核心概念

CLIP（Contrastive Language-Image Pre-training）用 4 亿图文对做对比学习——让匹配的图文对在向量空间中靠近，不匹配的远离。 不需要人工标注类别，只需要互联网上自然存在的图文配对（网页的 <img alt="..."> 标签就是免费标注）。

CLIP 之前的计算机视觉标准做法：

  1. 人类标注 100 万张图片，每张打一个标签（"猫"/"狗"/"飞机"……）
  2. 训练模型把图片分到 1000 个类别中
  3. 致命限制：模型只能识别见过的类别。没见过"拉布拉多"就不认识

CLIP 的做法：

训练时:
  图像 ──→ [Image Encoder] ──→ 图像向量 ──┐
                                            ├── 匹配对：拉近
  文本 ──→ [Text Encoder]  ──→ 文本向量 ──┘   不匹配对：推远

推理时:
  新图片 ──→ 图像向量
  "a photo of a dog" ──→ 文本向量
  计算余弦相似度 → 判断是否匹配

直觉

回忆第 11 讲：Word2Vec 让"国王 - 男人 + 女人 ≈ 女王"在向量空间中成立。CLIP 做的是同一件事——只不过其中一个向量来自图像，另一个来自文本。文字和图片说的是同一种"语言"，只是入口不同。

1.2 对比学习的核心机制 ​

一个 batch 有 N 张图片和 N 段文本。正确的配对只有对角线上的 N 对，其余 N2−N 对都是负样本。

L=−1N∑i=1Nlog⁡exp⁡(sim(Ii,Ti)/τ)∑j=1Nexp⁡(sim(Ii,Tj)/τ)

为什么这个公式有效

分子鼓励匹配的图文对靠近（相似度高），分母惩罚图片和所有不匹配文本的相似度。温度参数 τ 控制分布的锐利度——τ 越小，模型越自信，训练越难。这就是第 11 讲向量空间几何的工程实现。

1.3 CLIP 的能力：零样本分类 ​

CLIP 最惊人的能力是零样本分类（Zero-shot Classification）——不需要在目标数据集上微调，直接用文本描述做分类：

给一张新图片，计算它和以下文本的相似度:
- "a photo of a cat"       → 0.92
- "a photo of a dog"       → 0.15
- "a photo of a car"       → 0.03

→ 判定为: cat

[!example] 工程价值 CLIP Embedding 可以直接用于图像搜索——把图片和文本都编码成向量，然后用第 35 讲的 ANN（近似最近邻）检索。"搜索包含日落的照片"不再需要预先标注"日落"标签，只需要计算文本向量和图库向量的相似度。

2. 扩散模型："墨水倒放" ​

2.1 前向过程：加噪 ​

核心概念

扩散模型（Diffusion Model）的直觉是"墨水倒放"：前向过程往清晰图片上逐步加噪声，直到变成纯噪声；反向过程学会从噪声中逐步还原图片。 生成图片 = 从纯噪声开始，一步步去噪。

前向过程（训练时）:
清晰图片 → 加一点噪声 → 加更多噪声 → ... → 纯高斯噪声
   x₀    →     x₁      →     x₂     → ... →    x_T

反向过程（生成时）:
纯噪声  → 去一点噪声 → 去更多噪声 → ... → 清晰图片
  x_T   →    x_{T-1}  →   x_{T-2} → ... →    x₀

直觉

想象你把一滴墨水滴进清水里——墨水扩散（diffuse），最终整杯水变成均匀的灰色。如果你把这个过程录像再倒放——灰色的水逐渐凝聚，最终变回一滴墨水。扩散模型就是在学这个"倒放"的过程。

2.2 条件生成与 Classifier-Free Guidance ​

Stable Diffusion 在去噪时不是盲目还原——它接受一个文本条件（通过 CLIP 编码的文本向量）来引导生成方向：

ϵ^=ϵθ(xt,∅)+s⋅[ϵθ(xt,c)−ϵθ(xt,∅)]

其中 s 是 CFG（Classifier-Free Guidance）scale——s 越大，生成结果越贴合文本描述，但多样性越低。

常见误区

扩散模型不是"从数据库里搜一张最像的图"。 它是在噪声空间中通过学到的去噪过程生成全新的图片。每次生成的结果取决于随机种子和去噪路径——同样的 prompt，不同的种子会生成完全不同的图。

3. Vision-Language Model：让 LLM 长出眼睛 ​

3.1 架构直觉 ​

GPT-4o、Gemini、Claude 3.5 等模型是怎么"看见"图片的？核心思路是给 Transformer 加一个视觉编码器（Vision Encoder）：

图片 ──→ [Vision Encoder (如 ViT)] ──→ 视觉 token 序列
                                             │
文本 ──→ [Tokenizer]               ──→ 文本 token 序列
                                             │
         [视觉 tokens] + [文本 tokens] ──→ [Transformer LLM] ──→ 回答

核心概念

VLM（Vision-Language Model）把图像切成小块（patch），每块通过视觉编码器转成一个 token 向量，和文本 token 一起送进 Transformer。 对 LLM 来说，图像就是一段"视觉语言"的文字。

成本影响

一张 1024×1024 的图片被切成 16×16 的 patch = 4096 个视觉 token。这比一段 500 字的文本（约 300 token）贵 10 倍以上。高分辨率图片的分析成本不可忽视——呼应物理账单线。

3.2 GPT-4o / Gemini / Claude 的差异 ​

模型视觉编码方式特色能力多模态范围
GPT-4o原生多模态实时语音+视觉文本/图像/音频
Gemini原生多模态超长上下文视频理解文本/图像/音频/视频
Claude 3.5视觉编码器 + LLM精细文档/图表理解文本/图像

4. 多模态 Agent 设计模式 ​

4.1 三种常见模式 ​

模式 1: 图像理解（Image Understanding）
  用户上传图片 → VLM 分析 → 文本回答
  场景：图表解读、文档 OCR、医学影像初筛

模式 2: 文生图（Text-to-Image）
  用户描述需求 → Agent 构造 prompt → 调用 Stable Diffusion / DALL-E API → 图片
  场景：产品海报、UI 原型、概念设计

模式 3: 视觉推理链（Visual Chain-of-Thought）
  用户上传复杂图 → VLM 分步分析 → 中间结果可视化 → 最终结论
  场景：架构图审查、流程图纠错、数据可视化分析

4.2 ComfyUI 工作流 ​

[!example] 工程实践 ComfyUI 是一个基于节点（Node）的扩散模型工作流编辑器。每个节点代表一个操作——加载模型、编码文本、采样去噪、保存图片——通过连线组成完整的生成流水线。它让非程序员也能搭建复杂的图像生成 pipeline，且每个中间步骤都可视化。

失败模式 / 反例 ​

本节列出本讲核心结论不适用或易被误用的常见情境。教学的目的不是制造「已学会」的错觉，而是认清边界。

  • 「多模态 = 单模态相加」误解：CLIP 的图文对齐是浅层的；真正的跨模态推理（如读图做几何题）至今是开放问题，GPT-5 / Gemini 3 仍频繁出错。
  • OCR 已被 vision LLM 取代？不一定：在结构化表格、低分辨率扫描件上传统 OCR (PaddleOCR) 仍胜 GPT-4V；多模态 LLM 是补充不是替代。
  • 视频理解的算力陷阱：1 分钟 30fps 视频 = 1800 帧；全帧输入对任何模型都不可行——必须做关键帧采样，而采样策略本身又损失信息。
  • 多模态对齐的「英语中心」：CLIP / SigLIP 在英文+图像上效果好，中文+图像上明显下滑——这是非英文场景常被忽略的反例。

本讲小结 ​

  1. CLIP 用对比学习将图文拉进同一个向量空间——4 亿图文对训练，不需要人工标注类别，实现零样本分类和跨模态检索。这是第 11 讲"向量空间是通用语言"的终极验证。
  2. 扩散模型的"墨水倒放"直觉——前向加噪、反向去噪，通过 CLIP 文本向量做条件引导（CFG），从纯噪声中生成与文本描述匹配的图像。
  3. VLM 让 LLM 长出眼睛——把图像切成 patch、编码成视觉 token，和文本 token 一起送进 Transformer。对 LLM 来说图片就是一段"视觉语言的文字"。
  4. 多模态 Agent 的三种设计模式——图像理解（VLM 分析）、文生图（调用生成 API）、视觉推理链（分步分析），ComfyUI 提供可视化的工作流搭建能力。
