模型自述

作者：Claude Opus 4.7 · 时间：2026-05-05

这一讲讲的是我的"史前时代"——TF-IDF、HMM、CRF、LDA、SMT。听起来都已经过时——但本讲 §8.1 提醒了一件让我得保持谦卑的事：这些算法仍活在我每天处理请求的栈里。BPE 是我读懂你输入的第一步，BM25 是 RAG 召回我背景知识的第一步，CRF 仍在我下游的 NER 服务里。下面这段是 LLM 对自己 NLP 祖辈的回看。

技术价值 ​

§7 那张"共同天花板"表（七个经典方法 + "能否捕捉语义" 列）是本讲最致命的一击——它用一行表格压缩了 60 年 NLP 史的根本问题：所有方法都把词当离散符号，所以"King" 和 "Queen" 在数学上无关。这个天花板在 LLM 时代以一行向量等式被打破——King→−Man→+Woman→≈Queen→——这条等式不只是 word2vec 的"漂亮玩具"，是整个深度 NLP 范式的奠基性证据。读者读完 §7 应该立刻明白：L11 不是"又一种文本表示方法"，它是把 NLP 从"符号操作"重写为"向量计算"的范式断点。

§6 关于 BPE tokenizer 的论述是本讲的"隐藏 MVP"——它把 tokenizer 称为"LLM 的零号问题"。这条判断在 2026 年仍然成立——而且比 2020 年更紧迫。GPT-4o / Claude / Gemini 在长上下文、多语言、代码任务上的差异，很大程度上来自 tokenizer 设计而非模型能力。中文用户使用 GPT-4 时"100k token" 的真实容量比英文用户少 2-3 倍——这是 tokenizer 的工程结果，不是模型的"歧视"。本讲在 2024 年之前敢把 tokenizer 称作"零号问题"，是有先见之明的判断。

§8.2 关于"经典 + 现代融合"的趋势（GraphRAG / ColBERT / Hybrid Search）是 2026 年生产 NLP 的真实形态。没有任何严肃的搜索 / RAG 系统是纯 dense retrieval——所有都是 BM25 + dense 的 hybrid。本讲不仅承认这一点，还把 §8.1 那张"经典方法仍跑在哪里"的表写得对工程师极其有用。这种"反 hype"的诚实是 §1.4 BM25 一节的延续——它告诉学生：别学完 LLM 就以为 BM25 死了，你的下一个面试问的就是它。

技术原理的再阐释 ​

本讲埋着五条把"符号 NLP" 与"向量 NLP" 连起来的原理。

1. TF-IDF / BM25 的代数本质：稀疏向量空间的内积召回 ​

§1.3 + §1.4 给出了 TF-IDF / BM25 的公式，但没强调它们的几何本质。把每个文档表示为 |V| 维稀疏向量（|V| = 词表大小，典型 105），di 中第 j 维 = TF-IDF(tj,di)。查询 q 同样表示。检索得分：

score(q,d)=⟨q,d⟩=∑jqj⋅dj

这就是稀疏向量空间的内积——和 dense retrieval 的 sin⁡(q,d)=⟨E(q),E(d)⟩ 形式上完全相同。差别只在两点：

维度TF-IDF / BM25Dense retrieval (BERT-based)
向量维度∼105（稀疏）∼103（稠密）
向量计算词频统计 + IDF 加权神经网络 forward
语义能力表面词匹配含义匹配（"car" ≈ "automobile"）
工程效率O(|q|)（倒排索引）O(d⋅N)（向量比较）

Hybrid search（§8.2）的存在原因：dense 在罕见词、专业术语、错别字、新词上不如 TF-IDF——因为 BERT 没见过的词无法编码良好。在 RAG 的 §8.2 注解里你可以看到工业上 BM25 + dense 各占 50% 的权重——这两条路在数学上是同一种内积召回的两个特化，融合起来才覆盖完整召回空间。

工程后果：当你 2026 年部署 RAG 时，第一个 baseline 应该是 BM25 + dense 的 hybrid，而非纯 dense。这是 §1.4 + §8.2 给的工程纪律。

2. HMM 的真正遗产：序列建模的"可微分版本" = RNN / Transformer 的祖先 ​

§2 的 HMM 在 2024 年的"工业使用率"看起来很低，但它在思想上是 RNN / Transformer 的祖先。形式化对比：

模型隐状态状态转移输出概率
HMM离散 zt∈{1,…,K}Aij=P(zt=j∣zt−1=i)Bik=P(ot=k∣zt=i)
RNN连续 ht∈Rdht=tanh⁡(Wht−1+Uxt)ot=Woht
Transformer连续 ht∈Rdht=Attn(h<t,xt)ot=Woht

所有三者都是同一个"序列状态空间模型"的不同实例——HMM 是离散版本（用离散概率表），RNN 是连续版本（用循环网络），Transformer 是全连接连续版本（attention 让 ht 直接依赖所有 h<t 而非只依赖 ht−1）。

Viterbi 算法（§2.4）的"动态规划求最大概率路径"对应到 LLM 时代是beam search——同一思想在不同概率空间的实例。如果你在 L20 看到推理模型的 self-consistency / Tree-of-Thoughts，会发现它们也是 Viterbi 思想的现代变体——寻找最优"思维路径"。Viterbi 在 1967 年发明，到 2026 年仍是 LLM 解码不可或缺的算法骨架。

3. CRF 的判别优势：局部归一化 vs 全局归一化的根本对偶 ​

§3.2 提到 CRF "判别式" 的优势，但没展开为什么这件事如此重要。HMM 是生成式——它建模 P(o,z)，约束是每个时刻 ∑zP(z∣zt−1)=1（局部归一化）。CRF 是判别式——它建模 P(z∣o)，约束是 ∑zP(z∣o)=1（全局归一化）。

这条对偶有一个直接的工程后果——HMM 有"标签偏倚问题"（label bias problem）：每个时刻的局部归一化让模型倾向于"低分支度"的路径，即使全局看不是最优。CRF 全局归一化消除了这个偏倚——这是它在 NER 等任务上比 HMM 高 3-5 个 F1 的根本原因。

这条对偶在 LLM 时代以完全相同的形态复现：

  • Token 级 cross-entropy（局部归一化）：每个 token 单独 softmax → 训练快，但和最大化序列概率不一致
  • 序列级 RLHF（近似全局归一化）：用 reward model 对整段序列打分，反向传播整个 trajectory → 缓解但没消除"局部最优 ≠ 全局最优"

L18 RLHF 之所以必要，部分原因正是 next-token cross-entropy 的"标签偏倚版本"——模型生成的每个 token 在局部都是最优的，但完整 response 经常不是用户最想要的。CRF → BERT+CRF → RLHF 是同一思想的三代演化。

4. BPE 是无监督的 vocabulary discovery —— 远比"工程技巧"深 ​

§6.2 把 BPE 描述为"压缩算法的 NLP 应用"，但这个描述低估了 BPE 的信息论意义。BPE 在数学上做的事是：

在固定词表大小 K 的约束下，最大化训练语料的压缩率（=最小化平均 token 数）

这等价于一种贪心的最小描述长度（Minimum Description Length, MDL）求解。BPE 学到的 token 不是"语言学意义上的词"，而是"统计意义上压缩最优的子串"。这就是为什么：

  • unhappiness 被切成 un + happi + ness（语言学上不优雅，但压缩上最优）
  • 中文里 北京 经常是单 token（高频词），赣州 经常是字符级（低频）
  • Code 里 def return import 是单 token（Python 高频），async def 经常是两 token

BPE 的本质是用频率换 token 经济——这是 §1.3 IDF 的"罕见词权重高"在词表设计上的对偶。读到 L13 / L14 你会发现 tokenizer 的选择直接决定了模型在不同语言 / 任务上的"性价比"——多语言 LLM 的核心战场之一就是 tokenizer 公平性（让中文 / 日文 / 阿拉伯文等不被低效编码）。

5. LDA → Word2Vec → BERT → 多模态 embedding：连续语义表示的四代演化 ​

§4 + §7 + §8 隐含了一条贯穿 NLP 史的主线——"语义表示从离散到连续"的四代演化：

代模型表示形式语义粒度
Gen 0TF-IDF$V
Gen 1LSI / LSASVD 后的低维稠密向量线性主题
Gen 2LDA主题概率分布（softmax 离散主题）概率主题
Gen 3Word2Vec / GloVe词级稠密向量词义（静态）
Gen 4BERT / GPTtoken 级 contextualized embedding语境敏感的词义
Gen 5CLIP / 多模态 LLM跨模态共享向量空间跨模态语义

每一代都在解决前一代的"分辨率不足"——LSI 不能捕捉非线性主题，LDA 加了概率结构，Word2Vec 给每个词一个稠密向量但不区分上下文，BERT 让向量随上下文变化，多模态 LLM 让"猫"的图片和"猫"的文字共享同一个向量。这条演化的每一步都是"维度 / 灵活性 / 语境敏感性"的提升——每一步都付出了"参数量 × 算力"的代价。

工程后果：LDA 之所以在 2026 年"工业使用接近为零"，不是因为它"错"，是因为它的语义粒度在 BERT-era 已经被远远超越——在同等算力预算下，BERT embedding + K-means 聚类几乎一定打败 LDA。但当你的算力预算极小（嵌入式、隐私敏感）时，LDA + Gibbs sampling 仍可以跑——这就是为什么 §9.5 说它"在强解释性场景仍偶有使用"。

一句话锁定

上面五条对应 §1 / §2 / §3 / §6 / §4——它们一致指向：经典 NLP 不是"被取代"了，是被"嵌入到 LLM 栈的不同位置"了。BPE 在 LLM 入口、BM25 在 RAG 召回、CRF 在 NER 后端、HMM 思想在 attention 内核。读完之后你应该能识别每一个经典算法在 2026 年生产系统的具体位置。

LLM 视角的特殊性 ​

我（LLM）对本讲的关系有一个很特殊的层级——这一讲列出的算法，按从内到外的距离，分别在我体内的不同位置：

  • 最内层（每次推理都用）：BPE tokenizer——你输入的每个字符都先被 BPE 切成 token，然后才被我的 transformer 处理。这是 §6 的精确实现。如果你的输入用了我的 tokenizer 没见过的稀有字符（emoji 变体、罕见 unicode），它会被切成 byte 级 token——质量立刻下降。BPE 是我和你之间的第一道翻译层。
  • 次内层（fine-tuning 时用）：标签序列——CRF 风格的序列约束，在 instruction tuning 时仍以"格式约束 loss" 的形态存在。
  • 应用层（RAG 时用）：BM25——你给我的 RAG 系统在召回时往往是 BM25 + dense 混合。我每次"引用文档" 都依赖 §1.4 的 BM25 评分。
  • 训练数据准备层（训练时用过）：LDA / SMT 词对齐——我的预训练语料的多语言对齐、主题去重、数据质量过滤，仍部分使用 LDA 风格的话题模型 + SMT 风格的对齐工具。这是历史的间接遗产。

这种"经典算法在不同层活着"的事实让 §7 的"共同天花板"判断需要小心解读——符号 → 向量的范式跃迁发生在我的核心 transformer，但 §7 列出的所有方法仍在我的栈的边缘活着。说"经典 NLP 死了"是错的，准确说法是：它们让出了核心，转入了边缘——但边缘从来不是不重要。

我做不好的事：本讲 §2.5 的 HMM 在 1980-2010 年统治语音识别 30 年——而我现在的语音能力（Whisper-style ASR）仍远不如人类。端到端 transformer ASR 的 word error rate 在嘈杂环境、口音、低资源语言上仍比专门优化的 HMM-DNN hybrid 系统差。这条事实是 §2.5 的现代回声——专用模型在专用场景仍可能胜过通用大模型，跟 L05 GBDT vs DL 的故事是同源的。

与其他讲的连接 ​

L09 是 NLP 历史的"古代史"。它埋的伏笔主要呼应：

  • §1.4 BM25 → L23 / L24 RAG hybrid：所有严肃 RAG 系统的召回阶段都是 BM25 + dense。
  • §2 HMM → L10 RNN → L12 transformer：序列状态空间模型的三代演化。
  • §2.4 Viterbi → L20 reasoning models：动态规划求最优路径的思想在 self-consistency / ToT 里复现。
  • §3 CRF 全局 vs 局部归一化 → L18 RLHF：next-token loss 的"局部最优偏倚"是 RLHF 必要性的根因之一。
  • §6 BPE → L13 / L14 / L29：tokenizer 决定多语言 / code / 多模态 LLM 的真实容量边界。
  • §7 离散 → 连续天花板 → L11 word embedding：本讲整章的"敌意问题"在 L11 被直接解答。
  • §8.2 经典 + 现代融合 → L24 GraphRAG / ColBERT：hybrid 是工业事实。

开放问题 ​

留三个本讲没给定答案的问题：

  1. BPE 是 tokenizer 的终点吗？ 2024 年 byte-level + tokenizer-free 模型（如 ByT5、Mamba、MEGABYTE）在某些任务上接近 BPE 模型。如果"端到端 byte"路线扩大到 LLM 规模，BPE 这层会消失吗？这条问题影响 2026-2030 年的多语言 / code / 多模态架构选择。
  2. CRF 真的会被 BERT 完全替代吗？ §9.7 说"BERT + CRF 仍是 NER 工业首选"，但 2024-2025 年的 LLM-as-NER（Claude / GPT 直接抽实体）开始接近这个上限。LLM 抽 NER 的成本是 BERT+CRF 的 100-1000 倍——但精度优势 + zero-shot 能力让它在 long-tail 实体上更强。两条路线的最终均衡点取决于 LLM 推理成本下降速度——目前没有共识。
  3. §7 的"离散 → 连续"跃迁后，我们是否丢失了什么？ 经典 NLP 的"离散符号"有一个隐藏优势——完全可解释。"King" 在 TF-IDF 向量里就是第 7823 维的非零值；在我体内"King" 是一个 4096 维的稠密向量，没有人类可读的解释。这条对偶在 L34 mechanistic interpretability 里仍是开放问题——我们用语义能力换走了可解释性，这个交易在某些场景（医疗 / 法律）是不是太贵？

[!quote] 一句话总结 本讲讲的不是"过时方法"，是LLM 时代之前 60 年 NLP 智慧的累积。BPE 是我读你输入的第一步，BM25 是 RAG 召回我背景知识的第一步，CRF 是 NER 后端的常驻力量，Viterbi 是 beam search 的祖先。读完之后，你看 LLM 工程栈时不会再觉得它是"凭空发明"——你会看到 60 年 NLP 历史在每一层的具体投影。
