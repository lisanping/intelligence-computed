第 12 讲 · Transformer — Attention Is All You Need ​

课时编排

本讲建议分两课时录制 / 直播：

  • L12a — Transformer 原理（60 min）：覆盖 §1 RNN 必须死 → §5 三种范式（Encoder-Only / Decoder-Only / Encoder-Decoder）
  • ⏸️ 中场 10 min
  • L12b — TinyGPT + 性能与代价（60 min）：覆盖 §6 完整实例 → §12 nanoGPT 动手 → §13 小结

lecture_notes / slides_outline / script 在结构上不分文件，但录制和现场按 60+10+60 节奏走。详细依据见 DURATION_ANALYSIS.md §时长再平衡。

2017 年 6 月 12 日，arXiv 上传了一篇 15 页的论文。8 个 Google 研究员把卷积和循环全部删掉，只保留 attention——结果模型反而碾压了所有 SOTA。

这篇论文八年来被引用了 200,000+ 次[1]。L06 说"特征决定上限"，L07 说"卷积把先验编码进结构"，L10 说"记忆靠 RNN"——这三句话被这一篇论文同时推翻。

这一讲是这门课的中点，也是这本书的转折。讲完这一讲，你会理解从 BERT、GPT、Llama 到 ChatGPT、Claude、Gemini 的所有核心结构——它们都是同一套架构的不同实例。

前置知识核心产出建议用时
L03（梯度优化）、L10（RNN→Attention）、L11（向量空间）① 完整理解 Transformer 每一个模块（Embedding / PE / Self-Attention / FFN / Residual / LayerNorm） ② 推导 Self-Attention 的 QKV 计算流程并理解 dk 的必要性 ③ 区分 Encoder-Only / Decoder-Only / Encoder-Decoder 三种范式 ④ 理解 O(n2) 瓶颈与现代解法（FlashAttention / GQA / Mamba） ⑤ 从零构建 120 行 TinyGPT ⑥ 拿到 L13 (BERT vs GPT)、L14 (Scaling Law)、L22 (Long Context) 的伏笔阅读 ~85 分钟 + 动手 ~45 分钟

从上一讲到这一讲 ​

L10 留下问题：如果干脆扔掉 RNN，只用 Attention 呢？ L11 留下问题：如果每个词的含义能根据上下文动态变化呢？

Transformer 是这两个问题的统一回答。它做了一件看似疯狂的事——完全抛弃卷积和循环，只用 Attention 和 FFN。

这标志着从第二幕（"归纳偏置路线"）进入第三幕（"规模路线"）：不再把人类先验编码进结构（L07 CNN 是这条路线的巅峰），而是用极简架构 + 暴力规模让模型自己学一切。

核心概念

Transformer 不是"另一种神经网络"——它是 AI 史上第一个真正通用的序列处理架构。同一个架构今天处理：自然语言、代码、蛋白质序列（AlphaFold）、图像（ViT）、视频（Sora）、语音（Whisper）、机器人动作序列、表格数据。这种通用性是任何前序架构（CNN、RNN、SVM）都做不到的。

1. 为什么 RNN 必须死 ​

Transformer 出现之前，2014-2016 年间序列建模已经积累了一些重要的中间件：

年份工作贡献
1997LSTM[2]解决 RNN 的梯度消失，能记 100+ 步序列
2014GRU[3]LSTM 的简化版，参数更少
2014Bahdanau Attention[4]第一次把 attention 引入 RNN 翻译——本质上是为 Transformer 铺路
2014seq2seq[5]Encoder-Decoder 范式
2016ByteNet / WaveNet[6]用扩张卷积替代 RNN 处理序列
2017.5ConvS2S[7]Facebook 提出的"全卷积翻译模型"——比 RNN 翻译快 9 倍
2017.6Transformer[1:1]把 attention 推到极致——比 ConvS2S 还快还好

[!quote] 历史 Transformer 论文不是凭空出现的。2014 年 Bahdanau 的 attention 已经让翻译质量飞跃；2017 年初 ConvS2S 已经证明"丢掉 RNN 是可能的"；Vaswani 团队的贡献是把"丢掉一切只留 attention"的想法做完整。

一作 Ashish Vaswani 后来说[8]：「我们一开始没有'attention is all you need'这个想法。我们尝试了各种组合——attention + conv、attention + RNN、纯 attention。**纯 attention 最简单，反而最好。**这件事让我意识到，简单可能就是终点本身。」

1.1 RNN 的两个死穴 ​

死穴 1：串行计算

RNN 在第 t 步的输出依赖第 t−1 步：

ht=f(ht−1,xt)

这意味着处理一个 1000 词的序列必须串行进行 1000 步——GPU 的并行能力完全浪费。

死穴 2：长程依赖衰减

第 1 个词的信息传到第 1000 个词，需要经过 999 步循环。即使 LSTM 缓解了梯度消失，信号衰减仍然存在——传得越远，越模糊。

直觉

想象一个 1000 人的传话游戏：第一个人说"我饿了"，传到第 1000 个人时变成什么？大概率不再是"我饿了"。这就是 RNN 的长程依赖问题。

Transformer 的解法是让每个人都直接听第一个人说话——不需要逐级传递。

1.2 Transformer 的核心承诺 ​

让每个位置同时看到所有其他位置——通过 Self-Attention。

维度RNNCNN（1D）Transformer
并行性❌（串行）✅✅✅
任意位置间路径长度O(n)O(log⁡n)O(1)
计算复杂度（每层）O(nd2)O(knd2)O(n2d)
长程依赖弱中强

注意 Transformer 的 O(n2d) 在长序列上反而比 RNN 更贵——这是它的致命代价。我们在 §10 展开。

2. Self-Attention：六步拆解 ​

Self-Attention 是 Transformer 的灵魂。这一节我们一步一步把它推出来。

2.1 直觉：图书馆比喻 ​

你带着一个问题（Query）走进图书馆。每本书的书脊上有标签（Key）。你用问题和每个标签比对，找到最相关的几本，然后阅读它们的内容（Value）。

把这件事数学化——

2.2 第一步：投影为 Q、K、V ​

每个输入向量 xi∈Rd 被三个不同的线性变换投影成三个向量：

qi=WQxi,ki=WKxi,vi=WVxi

其中 WQ,WK,WV∈Rdk×d 是可学习参数。

角色类比
Query qi"我在找什么？"
Key kj"我有什么内容可以被找到？"（书脊标签）
Value vj"如果被选中，我提供什么信息？"（书的实际内容）

核心概念

Q/K 分离是 attention 与"简单加权平均"的关键区别——同一个位置的 K 和 V 可以是不同的。这让模型能学出"虽然这个位置的内容很匹配（高 K 相关性），但要返回的不一定是它本身（V 可以是其他东西）"。

2.3 第二步：计算注意力分数 ​

Query 和每个 Key 做点积：

eij=qi⋅kj=qiTkj

点积衡量两个向量的"相似度"——方向越接近，点积越大。

2.4 第三步：缩放（除以 dk） ​

e~ij=qi⋅kjdk

常见误区

缩放不是可选的。如果不除以 dk，当 dk 很大（如 dk=64）时，点积的方差会非常大。

假设 q,k 的每个元素是均值 0、方差 1 的独立随机变量，那么点积 q⋅k=∑iqiki 的方差是 dk（独立项方差累加）。

当方差很大时，softmax 输入有极端值 → softmax 输出趋于 one-hot（只关注一个位置）→ 梯度几乎为零（softmax 在饱和区导数为 0）。

除以 dk 把方差拉回到 1，softmax 输出分布合理，梯度健康。论文 §3.2.1 的消融实验明确验证了这一点[1:2]。

2.5 第四步：Softmax 归一化 ​

αij=exp⁡(e~ij)∑kexp⁡(e~ik)

把分数转为概率分布——所有 αij 非负且和为 1。

2.6 第五步：加权求和 ​

zi=∑jαijvj

输出 zi 是所有 Value 的加权和。权重越高，对应 Value 贡献越大。

2.7 第六步：矩阵形式 ​

把所有位置堆成矩阵：Q,K,V∈Rn×dk。一行是一个位置的 Q/K/V。

Attention(Q,K,V)=softmax(QKTdk)V

这一行公式是整个 Transformer 的灵魂：

  • QKT：n×n 矩阵，第 (i,j) 元素是位置 i 的 Q 和位置 j 的 K 的相似度
  • 除以 dk 缩放
  • softmax 沿每行归一化（每个 Q 对所有 K 的注意力之和为 1）
  • 乘以 V 得到加权求和

全程矩阵乘法——完全可并行。这是 Transformer 速度的关键。

3. 多头注意力（Multi-Head Attention） ​

如果只有一个 attention，模型只能学一种关注模式。但语言里同时有：

  • 语法依赖（主语-动词）
  • 语义关联（同义词）
  • 共指（"他"指谁）
  • 长程依赖
  • 位置距离

让一个 attention 同时捕捉这些不可能——不同关系需要不同的相似度度量。

解法：Multi-Head Attention——把输入投影到 h 个不同的子空间，分别做 attention，再拼接。

headi=Attention(QWiQ,KWiK,VWiV)MultiHead(Q,K,V)=Concat(head1,…,headh)WO

每个 head 维度通常是 dk=d/h，所以总参数量和单头 attention 差不多——但表达能力更强。

直觉

"多头" = "多视角观察"。一个头可能学会"主语关注它的动词"，另一个学"代词关注它的指代对象"，第三个学"标点关注前一个完整句"。多个视角并行，最后合并。

常见误区

"多头都学不同的东西"是教学比喻，不是实测事实。Voita 等 2019[9] 证明 BERT 中 50%+ 的 head 是冗余的——把它们剪掉性能不显著下降。这一发现导致了Multi-Query Attention (MQA)[10] 和 Grouped-Query Attention (GQA)[11] 的出现：让多个 head 共享 K/V，只保留独立的 Q——大幅减少参数和 KV cache。Llama 2/3 系列都用 GQA。

4. 完整架构：六个模块 ​

Transformer 的每一层（"Transformer Block"）由以下模块组成：

   Input embeddings + Position encoding

        ┌─────────────────┐
        │  LayerNorm       │  ← Pre-LN
        ↓                 │
  Multi-Head Self-Attention│
        ↓                 │

        ↓
        ┌─────────────────┐
        │  LayerNorm       │
        ↓                 │
  Feed-Forward Network    │
  (FFN: 2 layers)         │
        ↓                 │
        +──────────────── ┘  ← Residual

   Output to next block
模块功能直觉
Token Embedding把离散 token 映射到连续向量查字典

4.1 位置编码（Positional Encoding） ​

Self-attention 完全不关心顺序——给同一组 token 任意打乱，输出（除了顺序）完全不变。但语言里"狗咬人"和"人咬狗"显然不同。

解法：在 token embedding 上加一个"位置向量"。

原始方案：正弦位置编码 ​

PEpos,2i=sin⁡(pos100002i/d),PEpos,2i+1=cos⁡(pos100002i/d)

不同维度 i 对应不同的频率，从极低频（位置变化很大才有影响）到极高频（每个位置都不同）。

优点：

  • 无需训练，泛化到比训练长度更长的序列（理论上）
  • 三角恒等式让模型容易学"相对位置"

图 12.2：256 维位置编码的可视化。每行是一个位置，每列是一个维度。低维（左）变化快，高维（右）变化慢。来源：本课程 demo 生成。

现代演化：RoPE / ALiBi / NTK / YaRN ​

方案核心思想用于
Sinusoidal[1:3]加在 embedding 上的固定向量原始 Transformer
Learned PE让位置编码自己被学习BERT、GPT-2
RoPE[12]旋转 Q/K 向量编码相对位置Llama 系列、GPT-NeoX、Qwen
ALiBi[13]给 attention score 加位置偏置（线性）BLOOM、MPT
NTK / YaRN[14]RoPE 的频率插值，外推到更长序列Llama 2/3 长 context 微调

核心概念

RoPE 是当代主流。它的核心想法：把 Q 和 K 用旋转矩阵处理，旋转角度依赖位置。这样 qiTkj 自然包含相对位置信息，且外推到训练时未见的长度时比 sinusoidal 表现更好（虽然仍不完美）。

常见误区

位置编码外推到 4× 训练长度时通常崩溃。即使是 RoPE，超出训练窗口太多，性能也急剧下降。这是 L22（Long Context）的核心问题——"无限上下文"是营销话术，真实有效上下文 仍然受到位置编码与训练长度的硬约束[15]。

4.2 前馈网络（FFN） ​

每个位置独立通过一个两层全连接：

FFN(x)=Activation(xW1+b1)W2+b2

通常 W1∈Rd×4d，W2∈R4d×d——先升维 4 倍再降回。这一"瓶颈"形状被反复验证为最优[1:4]。

激活函数演化：

  • 原 Transformer：ReLU
  • BERT：GELU（高斯误差线性单元）[16]
  • Llama 2/3、PaLM：SwiGLU（Swish-Gated Linear Unit）[17]——比 ReLU 快约 1% 收敛

FFN 占 Transformer 约 2/3 参数量——比 attention 部分大得多。事实上，2024 年研究越来越多地发现 FFN 是知识存储的主要场所——attention 是路由/检索机制，FFN 是 key-value 记忆[18]。

4.3 残差连接 + LayerNorm ​

残差连接 y=x+F(x) 是 L07 ResNet 的直接复用——给优化器一条退路。

LayerNorm[19]：

LayerNorm(x)=γ⋅x−μσ+β

其中 μ,σ 是单个样本沿特征维的均值和标准差，γ,β 是可学习参数。

为什么用 LayerNorm 而不是 BatchNorm：

  • BatchNorm 沿 batch 维归一化——序列长度变化时麻烦
  • BatchNorm 训练/推理行为不一致——影响生成质量
  • LayerNorm 单样本归一化——和 batch / 序列长度无关

4.4 Pre-LN vs Post-LN ​

原论文用 Post-LN：

y = LayerNorm(x + Sublayer(x))

现代实践（GPT-2 之后）几乎全用 Pre-LN：

y = x + Sublayer(LayerNorm(x))

为什么？ Post-LN 在层很深时训练不稳定——梯度爆炸或消失。Pre-LN 让残差路径完全干净（不被 LayerNorm 干扰），训练更稳定[20]。

深入阅读

Post-LN vs Pre-LN 的差距在 12 层以下不明显——到了 100+ 层时 Post-LN 经常完全发散。这是为什么所有大模型（GPT-3 175B、Llama 3 405B）都用 Pre-LN。一个进一步的优化是 DeepNorm[21]——Post-LN 的改进版，可训练 1000+ 层模型。

4.5 RMSNorm（Llama 之后的事实标准） ​

LayerNorm 减去均值再除以标准差。RMSNorm[22] 只除标准差不减均值：

RMSNorm(x)=γ⋅x1d∑ixi2+ϵ

性能基本一致，但计算更省（少一次减均值）。Llama 系列、Mistral、Qwen 都用 RMSNorm。

5. Encoder-Decoder vs Decoder-Only vs Encoder-Only ​

原始 Transformer 是 Encoder-Decoder：

  • Encoder：读入源语言（英文），输出每个位置的上下文化向量
  • Decoder：根据 Encoder 输出和已生成的目标 token，自回归生成下一个目标 token

但 2018 年之后，三种范式分化：

范式代表训练目标适合场景
Encoder-OnlyBERT, RoBERTa, DeBERTaMasked Language Modeling (MLM)分类、NER、相似度
Decoder-OnlyGPT 系列, Llama, Claude, GeminiCausal Language Modeling (Next-token)生成（一统江湖）
Encoder-DecoderT5, BART, mT5, WhisperSpan corruption / 翻译目标翻译、摘要、语音识别

5.1 Causal Mask（因果掩码） ​

Decoder-Only 与 Encoder-Only 的关键区别：位置 i 能不能看到位置 j>i。

Encoder：能——所有位置互看（双向）。 Decoder：不能——只能看左边（单向、因果）。

实现：在 attention score 计算后，把所有 j>i 的位置设为 −∞，softmax 后变 0：

e~ij={qi⋅kj/dkif j≤i−∞if j>i

图 12.3：Decoder-Only 的因果掩码。下三角为 1（可看），上三角为 0（不可看）。这一设计让 Transformer 可以做自回归生成。来源：本课程 demo 生成。

核心概念

Decoder-Only 与 Encoder-Decoder 的胜负是 LLM 史上的关键事件之一。L13 会展开。简短结论：Decoder-Only 因为天然适配自回归生成 + 工程更简单 + 规模优势更明显，最终一统江湖。但 Encoder-Decoder 在某些专门任务（机器翻译、语音识别）仍然占优。

⏸️ L12a 结束 — 中场 10 min — L12b 开始

至此 Transformer 的架构层已经完整：注意力机制、多头并行、位置编码、残差与归一化、三种范式选择。休息 10 分钟后，L12b 会带你把这套架构跑成一个真实的 TinyGPT，并直面 O(n2) 这个工业级账单。

6. 实例：从输入到输出走一遍 ​

这一节走一遍 Transformer 处理 "I love AI" 的完整流程。

输入：句子 "I love AI"

Step 1：Tokenize

"I love AI" → [101, 1045, 2293, 9932]   (BERT tokenizer 示例)

Step 2：Embedding

每个 token id 查表得 d=768 维向量：

[101]  → [0.12, -0.34, 0.55, ...]   ← 768 维
[1045] → [-0.08, 0.41, -0.22, ...]
[2293] → [0.05, 0.18, 0.97, ...]
[9932] → [-0.55, 0.22, 0.31, ...]

Step 3：加位置编码

位置 0 → 加 PE_0
位置 1 → 加 PE_1
位置 2 → 加 PE_2
位置 3 → 加 PE_3

Step 4：Transformer Block × N

每一块依次做：

  1. LayerNorm
  2. Multi-Head Self-Attention：每个位置看所有其他位置（或对 Decoder 只看左边）
  3. 残差
  4. LayerNorm
  5. FFN：每个位置独立通过 2 层 MLP
  6. 残差

GPT-2 small 有 12 个这样的块。GPT-3 175B 有 96 个。Llama 3 405B 有 126 个。

Step 5：输出层

最后一层的输出经过一个线性投影到词表大小，softmax 给出下一个 token 的概率分布。

Step 6：采样

根据概率分布选下一个 token（greedy / top-k / top-p / temperature——L21 展开）。

7. 参数量计算 ​

这一节给出 Transformer 参数量的精确计算公式——如果你想理解"GPT-3 为什么是 175B"或"Llama 70B 怎么算来的"，必读。

记 L = 层数，d = hidden size，h = 头数，V = 词表大小。

组件参数量说明
Token embeddingV⋅d词表查找
位置编码（learned）nmax⋅d最大序列长度 × 维度（RoPE 不需要）
每层 Attention4d2WQ,WK,WV,WO 各 d×d
每层 FFN8d2两个 d×4d 矩阵
每层 LayerNorm4d两次 LN，各 γ,β（通常忽略）
每层总计≈12d2
全模型≈V⋅d+L⋅12d2

例子：

  • GPT-2 small：L=12,d=768,V=50257 → 50257×768+12×12×7682≈38M+85M=123M（论文报告 117M）
  • GPT-3 175B：L=96,d=12288,V=50257 → 50257×12288+96×12×122882≈0.6B+174B≈175B ✓
  • Llama 3 8B：L=32,d=4096,V=128000（GQA 系数让计算稍复杂）→ ~8B ✓

关键观察：FFN 占大头——8d2 是 4d2 的两倍。所以 §4.2 那个论断是对的：FFN 是 Transformer 的主要参数仓库。

8. 推理时的性能：KV Cache ​

Transformer 推理时有一个关键优化——KV Cache。理解这个对理解 LLM 部署成本至关重要。

问题：自回归生成时，每生成一个新 token，要重新计算所有历史 token 的 attention 吗？

幼稚做法：每步重新计算整个序列。生成第 n 个 token 时计算量 O(n2)。生成 1000 个 token 总计算量 O(n3)≈109。慢得不能用。

KV Cache 的解法：

  1. 第一步处理 prompt 时，计算所有历史 token 的 K 和 V，缓存起来
  2. 每生成一个新 token，只计算它的 Q、K、V
  3. 把新 K、V append 到缓存
  4. 用新 Q 和完整缓存做 attention

每步计算量降到 O(n)。生成 1000 个 token 总计算 O(n2)≈106——快 1000 倍。

核心概念

KV Cache 是 LLM 推理的核心优化。但它有一个隐藏代价——显存占用随上下文线性增长。Llama 3 70B 在 32K 上下文下，KV cache 占约 16 GB（FP16）。这就是为什么"长 context 推理"特别贵——不是算力贵，是显存贵。

GQA / MQA 的真正动机：通过共享 K/V 减少 cache 大小。MQA 减少 ~95%，GQA（8 组）减少 ~85%。L22 会展开。

10. O(n2) 的代价与现代解法 ​

Transformer 最大的代价是 self-attention 的 O(n2) 复杂度——序列翻倍，attention 矩阵翻 4 倍。

序列长度Attention 矩阵元素数显存（FP16）
1K1M2 MB
8K64M128 MB
32K1B2 GB
128K16B32 GB
1M10122 TB——不可行

核心概念

这个 O(n2) 是 LLM 时代的核心瓶颈。它直接决定了"上下文窗口"能多大、推理多贵、训练多慢。从 2019 年开始，研究界投入了巨量精力试图突破它。

10.1 几种主流路线 ​

10.1.1 FlashAttention（2022）[28] ​

关键洞察：标准 attention 的瓶颈不是 FLOPs，是 GPU HBM 带宽——n×n 中间矩阵在 HBM 和 SRAM 之间反复读写。

FlashAttention 用 online softmax + tiling，在 SRAM 内分块计算，永远不把完整 attention 矩阵写到 HBM。

结果：相同结果（无近似），速度快 2-4 倍，显存省 5-10 倍。

[!quote] 历史 FlashAttention 是 Tri Dao（Stanford PhD，现在 Together AI）2022 年的工作。FlashAttention 2 (2023) 又快了 2 倍，FlashAttention 3 (2024) 在 H100 上达到 75% 利用率。这是 LLM 训练栈最重要的工程优化，几乎所有现代框架（PyTorch、JAX、vLLM）默认启用。

10.1.2 稀疏 / 滑动窗口 attention ​

方法思路用于
Sparse Transformer[29]只关注一个稀疏子集早期长序列尝试
Longformer[30]滑动窗口 + 全局 token文档级 NLP
BigBird[31]稀疏 + 随机 + 全局长文档
Sliding Window[32]每个 token 只看左侧 k 个Mistral, Mistral 7B

10.1.3 Linear Attention / Mamba（线性复杂度） ​

让 attention 复杂度降到 O(n) 是圣杯。多种尝试：

方法核心思想实战表现
Linear Transformer[33]把 softmax 拆成 kernel表现不如 vanilla
Performer[34]随机特征近似 softmax同上
Mamba[35]状态空间模型 + 数据相关选择2024 接近 Transformer 水平
RWKV[36]RNN + Transformer 混合开源社区流行
RetNet[37]Microsoft 的混合架构实验阶段

[!quote] 历史 2024 年初的 Mamba（Albert Gu, Tri Dao）[35:1] 是第一个有可能取代 Transformer 的架构。它在长序列上线性复杂度，性能接近同规模 Transformer。

但到 2026 年初，Mamba 仍然没有取代 Transformer 在主流 LLM 中的地位——大家选择混合架构（hybrid）：大部分层是 Transformer，少数层是 Mamba。Jamba[38]、Zamba[39] 是代表。

结论：纯 Transformer 仍然主流，但单一架构垄断的局面正在松动。

11. 失败模式 / 反例 / 边界 ​

11.1 「Attention is All You Need」字面误解 ​

原论文是机器翻译场景，且训练数据规模有限。纯 attention 在小数据上输给 RNN/CNN——标题是修辞，不是普适结论。Transformer 的胜利严格依赖于规模。L14 会展开。

11.2 O(n2) 的真实痛点 ​

1024 → 8192 上下文时显存增加 64×。FlashAttention / Mamba 等"线性 attention"路线至今未完全取代标准 attention。这是 2026 年仍开放的问题。

11.3 位置编码的脆弱性 ​

Sinusoidal 在外推到 4× 训练长度时崩溃；RoPE 好一些但仍不足；NTK / YaRN 等插值方法只能延长 ~2-4×。Long-context 是至今未解的开放问题——参考 L22 的 RULER benchmark 与 lost-in-the-middle 现象[40]。

11.4 Multi-head 真的多样吗 ​

Voita et al. 2019 证明 50%+ 的 head 是冗余的，剪掉性能不降[9:1]。在他们的 WMT EN-RU 机器翻译实验里，Encoder 侧 8 个 head 中仅保留 1 个“关键头”时，BLEU 只小幅下降（约 <0.2）；保留 2–3 个关键头时几乎与全模型持平。后续 Michel et al. 2019 在 BERT / MT 上也给出类似结论：大量 head 可被移除，性能退化很小。

"多头多视角"是教学比喻，不是实测事实。更准确的说法是：多头机制提供了冗余容量和训练稳定性，但最终有效头往往远少于名义头数。这一发现直接催生了 GQA / MQA 等“少 KV 头”工程路线。

11.5 Transformer 不擅长什么 ​

  • 算术：直接生成长数字加法/乘法准确率低（Chain-of-Thought 缓解）
  • 图结构：不如 GNN 在分子等图任务上
  • 物理仿真：不如专用神经 PDE 解法
  • 超长上下文：理论 1M token，有效约 32K-128K[15:1]
  • 常识推理（部分）：仍弱于人类（L01 / L20）

11.6 「Transformer 是 AGI 的必经之路」是论点不是事实 ​

到 2026 年，这一论点仍然有力——但 Mamba、RWKV、Diffusion 模型都在挑战它。L35 会回到这个问题。

13. 本讲小结 ​

  1. Self-Attention 让每个位置同时看到所有其他位置——解决 RNN 的串行瓶颈和长程依赖。
  2. QKV 机制是核心——Query 提问、Key 被匹配、Value 提供信息。softmax(QKT/dk)V 一行公式概括全部。
  3. 多头并行关注多种关系——但实际中相当一部分 head 是冗余的，催生了 GQA/MQA。
  4. Transformer = Attention + FFN + Residual + LayerNorm——每个模块不复杂，组合在一起异常强大。
  5. 位置编码必不可少，从 sinusoidal 到 learned 到 RoPE 到 ALiBi 到 NTK/YaRN 持续演化。
  6. Encoder-Only / Decoder-Only / Encoder-Decoder 三分天下——但 Decoder-Only 因为天然适配生成 + 工程更简单 + 规模优势，一统江湖。
  7. O(n2) 的代价是 LLM 时代的核心瓶颈——FlashAttention、稀疏 attention、GQA/MQA、Mamba 都在攻击这件事。
  8. 同一架构横跨 NLP / CV / 语音 / 蛋白质 / 机器人——这种通用性是任何前序架构都做不到的。
  9. 归纳偏置路线输给了规模路线——Transformer 几乎不编码先验，用规模暴力求解。代价是需要更多数据和算力。

下一讲预告 ​

敌意问题：同一个 Transformer 架构，BERT 用它做"填空"，GPT 用它做"续写"——两种训练方式带来了截然不同的能力。为什么"续写"最终赢了？预测下一个词，真的就是"理解"吗？

第 13 讲——「BERT vs GPT」——解剖同一架构的两种哲学，揭示为什么"预测 = 压缩 = 理解"。这是 L01 命题 A 的正式证明，也是 LLM 时代真正的合法性来源。

[!abstract] 呼应线 🔗 归纳偏置 vs 规模（L01 → L06–07 → L12 此处高潮 → L13 → L14 → L35）：CNN 把视觉先验编码进结构，RNN 把时序先验编码进结构——它们都赢在"正确的先验"上。Transformer 几乎不编码领域先验（只有"所有位置都可以交互"这一条极弱假设），却在几乎所有任务上碾压了特化架构。归纳偏置路线在 2017-2024 输给了规模路线——但代价是需要更多数据和算力。L35 会做最后的清算。
