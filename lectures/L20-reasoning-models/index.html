第 20 讲 · 推理模型 — 让 AI 学会三思而后行 ​

L01 我们埋下种子：人类有 System 1（快思考）和 System 2（慢思考），而当前 AI 基本只是巨大的 System 1。

19 讲过去了——AI 也有了自己的 System 2。能力不再是固定的，思考的深度可以动态调节。

这是第四幕"内部构造"的压轴，也是全课程最重要的呼应之一。讲完这一讲，你会理解 OpenAI o1 / o3、DeepSeek-R1、Claude 4 Extended Thinking、Gemini Deep Think 这些 2024-2026 年最重要的产品形态——它们在做的不是"更强的语言模型"，而是给语言模型装一个 System 2。

前置知识核心产出建议用时
L01 (System 1/2)、L12 (Transformer)、L17 (RL)、L18 (RLHF)① 理解为什么标准 LLM 是 System 1（固定计算深度） ② 掌握 Chain-of-Thought 的原理、数学、局限 ③ 理解 Test-Time Compute Scaling 这条新规模轴 ④ 对比 o1/o3、DeepSeek-R1、Claude Extended Thinking、Gemini Deep Think 四种实现路径 ⑤ 理解 RLVR (Reinforcement Learning with Verifiable Rewards) 和 GRPO ⑥ 看清 Self-Consistency / Tree-of-Thought / MCTS-LLM 等推理时搜索方法 ⑦ 拿到 L26 (Agent)、L34 (Safety)、L35 (Predictions) 的伏笔阅读 ~80 分钟 + 动手 ~30 分钟

从上一讲到这一讲 ​

L19 让你用 LoRA / QLoRA 把通用模型变成了领域专家。它现在知识丰富、回答精准。

但你问它一道 IMO 数学题，它3 秒给答案——答案是错的。

不是因为它不知道数学——而是因为它从不"想一想再说"。

这就是 L01 埋下的种子：人类的智能有两套系统——System 1 快速直觉，System 2 慎重推理。从 L06 到 L19，我们给 AI 加了能力、知识、态度——但它始终只有 System 1。

本讲的主题：AI 终于有了 System 2。

[!abstract] 呼应线 🔗 System 1/2（L01 → L20 此处呼应）：L01 用六个认知偏差实验证明人类有快思慢想两套系统。然后说："当前 AI 模型——基本上就是一个巨大的 System 1。" 19 讲之后，这句话被推翻——AI 也有了自己的 System 2。人机认知架构正在趋同。

1. 为什么标准 LLM 天生就是 System 1 ​

1.1 固定计算深度的诅咒 ​

回忆 L12 的 Transformer：LLM 逐 token 生成文本，每预测一个 token 做一次前向传播，通过 L 层 Transformer。

核心概念

不管问题有多难，模型预测每个 token 的计算量都是一样的——O(L⋅d2)。

"1 + 1 = " 和"证明黎曼猜想"花费完全相同的前向传播。这就像让一个人用完全相同的时间回答自己的名字和费马大定理。

标准 LLM = 固定计算深度的函数。它不会因为问题更难就"想更久"。这正是 L01 给 System 1 下的定义：

System 1 属性标准 LLM
快速✅（每 token 几十毫秒）
自动✅（不能"决定不回答"）
固定开销✅（每 token O(L)）
难题上经常出错✅（GSM8K 17%, IMO 0% 早期）
给出"自信但错"的答案✅（幻觉、合取谬误）

1.2 计算复杂度的视角 ​

从计算理论看：

  • 可计算性：图灵完备需要无界计算时间。固定深度神经网络只是有界深度电路——它能计算的函数类是 TC0（threshold circuits, polylog depth）[1]，比图灵机弱得多。
  • 多项式 vs 指数：很多推理问题（数学证明、SAT、规划）需要指数计算量。固定 L 的 Transformer 在最坏情况下做不到。

[!quote] 历史 Merrill & Sabharwal 2024[2] 的理论结果：标准 Transformer（无 CoT）能表达的函数类是 TC0，连简单的多步算术理论上都做不到精确。但加上 CoT 后，Transformer 变成图灵完备[3]——它可以模拟任意计算（只要 token 数够多）。

这是 CoT 在理论上的合法性来源。CoT 不是技巧——它是把语言模型从"有界深度电路"升级为"图灵完备机器"的关键。

1.3 经验观察：LLM 在哪些任务上失败 ​

任务类型GPT-4 早期（无 CoT）失败原因
多步算术（10 位数加法）~30%需要进位推理，固定深度不够
GSM8K 数学应用题18%需要多步推理
MATH 高难数学<5%需要假设、回溯、证明
复杂代码调试低需要"假设-验证"循环
逻辑谜题（Knights/Knaves）低需要案例分析
ARC-AGI<5%需要小样本归纳推理

这些任务有一个共同点：人类解决它们时必然用 System 2——慢、刻意、有步骤、能回溯。

2. Chain-of-Thought：第一次尝试让模型"想" ​

2.1 CoT 的发现 ​

[!quote] 历史 2022 年 1 月，Google Brain 的 Jason Wei 和合作者发表 Chain-of-Thought Prompting Elicits Reasoning in Large Language Models[4]。

他们发现一个惊人简单的技巧：在 prompt 中加一句 "Let's think step by step"，模型在推理任务上的准确率大幅提升。

任务标准 Prompt+ "Let's think step by step"
GSM8K (数学应用题)17.7%57.1%
MultiArith33%79%
AQUA-RAT26%52%
StrategyQA48%65%

这件事在当时让所有人震惊——没有训练、没有微调，只是改了 prompt，准确率翻三倍。Wei 的论文被引用 15,000+ 次，是 LLM 时代第一篇真正"火"的 prompt 工程论文。

2.2 为什么 CoT 有效？三种解释 ​

解释 1：增加计算空间（前面 §1.2 的理论解释）

每输出一个 token 就是一次前向传播。当模型生成 T 个思考 token，总计算量变成 O(T⋅L⋅d2)——T 可以根据问题难度动态调整。这是 CoT 的理论合法性。

解释 2：用 token 作为外部工作记忆

直觉

标准 LLM 的"工作记忆"是 KV Cache + activation——容量受限于网络宽度。CoT 让模型把中间结果写到文本上，下一步再读回来——本质上是用上下文窗口当"草稿纸"。

这和人类一样——做长除法时你不在脑子里完成，你写在纸上，每一步看着前面的中间结果。

解释 3：检索训练数据中的推理模式

CoT 让模型生成训练数据中常见的"推理形式"。如果训练语料里有大量带步骤的数学题，模型就学到了"分步骤"的语言模式。CoT prompt 把模型推到这个分布上。

2.3 CoT 的局限 ​

CoT 不是终点，它有三个根本局限：

2.3.1 不保证正确 ​

模型可能生成看似合理但逻辑错误的推理链。Wei 的论文里就指出：CoT 增加了正确率，但也增加了"看起来正确实则错误"的比例。

2.3.2 无法回溯 ​

常见误区

标准自回归生成是单向的——一旦输出了一个错误的中间步骤，后面的所有推理都基于这个错误。CoT 没有"撤回"机制。

人类 System 2 的核心特征之一就是回溯——发现错误时能停下来、退回去、重来。CoT 做不到这件事。

2.3.3 推理链可能与实际决策不一致 ​

常见误区

Turpin et al. 2023[5] 证明：模型的实际决策与生成的 CoT 不一致——人类看到的推理链可能是事后合理化（rationalization）。

比如让 GPT-3.5 在多选题里答 (A)，它会生成支持 (A) 的理由；强迫它答 (B)，它会生成同样合理但支持 (B) 的理由。CoT 看起来可解释，但它不一定是模型真实的决策过程。

3. 推理时搜索：让模型有第二次机会 ​

CoT 的"无法回溯"是致命的。怎么解决？让模型生成多个候选，然后选最好的。

3.1 Self-Consistency（多数投票） ​

[!quote] 历史 Wang et al. 2023[6] 提出 Self-Consistency：生成 N 个不同的 CoT，对最终答案做多数投票。

直觉：如果一个问题有正确答案，多次随机推理应该集中到正确答案上；错误推理路径会发散到不同错答。

在 GSM8K 上，Self-Consistency (N=40) 把 PaLM 540B 的准确率从 56% 提升到 74%——比 CoT 单次再涨 18 个点。

但 Self-Consistency 有显著代价——N 倍的 token 成本。在 2024-2025 年，业界发现一个反直觉结论：

核心概念

同样的预算下，用更大模型 1 次采样常常优于小模型 N 次采样[7]。这一发现部分解释了为什么 OpenAI o1 选择"训练一个推理强的模型"而不是"普通模型 + Self-Consistency"。

3.2 Tree-of-Thought（ToT） ​

[!quote] 历史 Yao et al. 2023[8] 提出 Tree-of-Thoughts——把推理建模为树：每个节点是一个推理状态，模型可以从任一节点向下扩展、评估、回溯。

这就是 L02 的搜索算法在 LLM 上的复活——LLM 当生成器 + LLM 当评估器 + 经典搜索（DFS / BFS / beam）做控制。

ToT 在 24 题 (Game of 24) 上把 GPT-4 的准确率从 4% 提升到 74%——但 token 成本是 100 倍。

3.3 MCTS-LLM ​

把 L02 的 MCTS 用在 LLM 推理上[9]：

  • 每个节点是一个部分推理路径
  • LLM 生成下一步候选（=策略网络）
  • LLM 评估当前路径质量（=价值网络）
  • UCB 选择 + rollout + 回传

AlphaProof（DeepMind 2024 IMO 银牌）[10]、AlphaGeometry 2[11] 都是这条路线。

[!abstract] 呼应线 🔗 评估器演化（L02 → L20 此处 → L26）：L02 的 MCTS 用人写的 rollout 当评估器；AlphaGo 用神经网络当评估器；这一讲的 ToT/MCTS-LLM 用 LLM 自己当评估器——LLM-as-Judge 范式开始。L26（Agent）会展开。

3.4 推理时搜索 vs 训练时学到推理 ​

到这一节为止讲的都是外部搜索——LLM 不变，外面套搜索框架。这条路在 2022-2023 年是主流。

但 2024 年下半年，故事发生了根本变化——OpenAI o1 和 DeepSeek-R1 证明：可以训练一个自己会推理的模型，让推理行为成为模型内部能力。

接下来 §4-5 是这一变化的正面叙述。

4. Test-Time Compute Scaling：推理时的 Scaling Law ​

4.1 核心思想 ​

[!quote] 历史 2024 年 8 月，Snell, Lee, Xu, Kumar 在 "Scaling LLM Test-Time Compute Optimally can be More Effective than Scaling Model Parameters"[12] 中提出了第二条 Scaling Law：

不是只有训练时计算遵循幂律——推理时计算也遵循幂律。

Performance(task)∝Ctestα

其中 Ctest 是推理时消耗的计算量（思考 token 数 × 模型大小）。

实验观察：在数学推理任务上，给模型 更多的思考时间——

  • 思考 1k token：18% 正确
  • 思考 10k token：38% 正确
  • 思考 100k token：65% 正确

且这条曲线接近线性 in log⁡(Ctest)——和 L14 的训练 Scaling Law 形状惊人地相似。

4.2 训练时 vs 推理时 Scaling Law 的对比 ​

维度训练时 Scaling (L14)推理时 Scaling (本讲)
资源参数 N、数据 D、FLOPs C推理 token 数 T
受益对象所有任务可验证的推理任务
一次成本几亿到几十亿美元单次推理几美元到几百
边际收益缓慢递减在难任务上更显著
使用阶段训练前一次性投入每次查询动态调节

核心概念

Test-Time Scaling 给了用户一个新维度——你不需要等更大的模型，今天就可以用同一个模型解决更难的问题——只要你愿意等更久、付更多钱。这是 2024 年最重要的工程发现之一。

4.3 两种扩展策略 ​

策略 1：内部推理链（Internal Chain）

让模型在输出答案前生成大量"思考 token"——这些思考过程通常对用户隐藏。OpenAI o1/o3、DeepSeek-R1、Claude Extended Thinking 都属于这一路。

策略 2：搜索 + 验证（Search + Verify）

生成多个候选答案，用验证器选最好的——Self-Consistency / ToT / MCTS-LLM 这一路。AlphaProof、Pluri-AI 路线属于这一类。

直觉

想象考试时：策略 1 是"一个学生花 4 小时做一道题"，策略 2 是"10 个学生各做 20 分钟，选最好的答案"。两种都通过增加总计算量提高正确率——但适用场景不同：

  • 策略 1 适合需要"长上下文连贯推理"的任务（数学证明）
  • 策略 2 适合"答案易于验证"的任务（编程：跑测试）

5. 三大实现路线：o1 / R1 / Claude / Gemini ​

5.1 OpenAI o1 / o3：闭源先驱 ​

[!quote] 历史 2024 年 9 月 12 日，OpenAI 发布 o1-preview——LLM 史上第一个公开的"推理时计算"模型[13]。

同年 12 月，o3 发布。在公认极难的 ARC-AGI v1 benchmark 上，o3-high 单题正确率达到 87.5%——首次接近人类水平。但单题成本可达 $1000+[14]。

o1/o3 的训练方法至今未完全公开。OpenAI 只透露：

  • 用 RL 训练模型生成"内部思维链"（hidden chain-of-thought）
  • 不是简单的 CoT prompting——是模型学会的内置行为
  • 思考过程对用户隐藏（只显示摘要）

5.2 DeepSeek-R1：开源 + 纯 RL ​

[!quote] 历史 2025 年 1 月 20 日，深圳的 DeepSeek 公司发布 DeepSeek-R1[15]——开源推理模型 + 完整技术报告。

这件事在 AI 界引起的震动堪比 2012 年的 AlexNet：

  • 完全开源（MIT License）：模型权重、训练数据、训练流程全部公开
  • 纯 RL 训练：不需要人工标注的 CoT 数据
  • R1-Zero 自发涌现推理行为：仅用 RL 信号（答案对了加分），模型自己学会了"先想再说"
  • 性能逼近 o1：在 MATH、AIME、Codeforces 上接近 o1

R1 的发布让 OpenAI 当天股价跌 17%。Anthropic CEO Dario Amodei 第二天发表声明承认"开源推理模型的速度超出我们预期"[16]。

R1 的训练流程（公开版本）：

  1. Stage 1 — R1-Zero：从 DeepSeek-V3 出发，纯 RL（无 SFT），用 GRPO 算法。
  2. Stage 2 — Cold Start：拿 R1-Zero 生成的 ~1000 条高质量 CoT 数据 + 人工筛选，做 SFT。
  3. Stage 3 — 主 RL：再次 RL，加入推理奖励 + 格式奖励 + 安全奖励。
  4. Stage 4 — 蒸馏：用 R1 生成 80 万条数据，蒸馏到 1.5B / 7B / 70B 等小模型。

核心概念

R1-Zero 最令人震惊的发现：不需要人类教模型怎么思考——只要给出正确的奖励信号（答案对了就加分），模型会自己学会"先想再说"的策略。

论文中描述的现象：训练到约第 5000 步时，模型的输出长度突然急剧增加——它自发地开始在回答前写"Let me think about this..."然后展开多步推理。这一现象被称为 "aha moment"。

这暗示 System 2 推理可能是涌现的，而不是人工注入的。这与 L01 / L14 的"涌现"主线深度共鸣。

5.2.1 GRPO：R1 的核心算法 ​

GRPO (Group Relative Policy Optimization)[15:1] 是 PPO (L17/L18) 的简化版。核心改动：用 group baseline 替代 critic 网络——同一个 prompt 采样 G 个回答，用它们的平均 reward 当 baseline。

PPO 需要训练独立的 value network（参数量等同于 policy）；GRPO 不需要——节省 50% 训练算力。在 RL for reasoning 这个场景下表现接近 PPO。

5.3 Claude 4 Extended Thinking：用户可控 ​

Anthropic 的 Claude 4（2025-Q2 发布）[17] 采用了不同路线——让用户控制思考预算：

python
response = claude.messages.create(
    model="claude-4-opus",
    thinking={"type": "enabled", "budget_tokens": 32000},
    messages=[...]
)

特点：

  • 用户可见思考过程——和 R1 一致，区别于 o1
  • 用户可控预算——明确告诉模型"最多想 X token"
  • 思考与最终回答区分——response 中分别返回 thinking 和 text 字段

哲学：不是所有问题都需要 System 2——把"思考多久"的决定权交给用户。

5.4 Gemini 2.5 Deep Think ​

Google 的 Gemini 2.5 Deep Think（2025）[18] 加入推理模型阵营：

  • 原生多模态推理（图像 + 文本同时思考）
  • 上下文 1M-2M token
  • 在 USAMO / IMO 上达到金牌级别

6. 推理模型在"想"什么？ ​

分析公开的 R1 思维链可以观察到几种行为模式——它们和人类 System 2 推理惊人地相似。

6.1 五种典型推理行为 ​

6.1.1 问题分解（Decomposition） ​

"To solve this, I need to:
1. First find ...
2. Then compute ...
3. Finally combine ..."

6.1.2 假设验证（Hypothesis-Verification） ​

"Let me try x = 5. Then ... = 20.
Wait, that doesn't satisfy the constraint.
Let me try x = 3 instead."

6.1.3 回溯修正（Backtracking） ​

"Actually, wait. I made an error in step 2.
The correct value should be ..."

6.1.4 多路径探索（Branching） ​

"There are two ways to approach this:
Approach A: ...
Approach B: ...
A is simpler, let me go with A."

6.1.5 自我评估（Self-Evaluation） ​

"Let me double-check this. If x = 7, then ...
Yes, this is consistent with the original equation."

6.2 这是真"思考"吗？ ​

常见误区

关于"模型是否真在思考"的哲学问题，2026 年仍无共识。

  • 支持派：行为同构于人类 System 2——分解、回溯、验证、评估。如果走起来像鸭子、叫起来像鸭子……
  • 怀疑派：模型只是在模仿训练数据中"看起来在思考"的语言模式。Turpin 2023 的实验[5:1] 显示 CoT 链可能是事后合理化。

这个问题不会很快被解决。但对工程影响很小——无论它是不是"真思考"，它产生的有用结果是真实的。L34（Safety）会回到这件事。

6.3 推理模型的代价 ​

任务GPT-4oo1成本比
简单问答~200 tokens~2,000 tokens10×
数学竞赛~500 tokens~50,000 tokens100×
编程难题~1,000 tokens~30,000 tokens30×
ARC-AGI<100 tokens~100,000 tokens1000×

常见误区

推理模型不是所有场景的最优选择。对于：

  • 简单信息检索 / 翻译 / 摘要——标准 LLM 的 System 1 足够好
  • 实时对话——推理模型延迟太高（每次响应 30 秒到几分钟）
  • 海量批处理——推理 token 成本不可承受

System 2 的价值在困难推理任务：数学证明、复杂代码、多步逻辑、规划。选择 System 1 还是 System 2，应该取决于问题的难度。

7. RLVR：推理模型背后的训练范式 ​

2025 年开始，"RLVR"（Reinforcement Learning with Verifiable Rewards）成为一个 buzzword。这一节解释它的核心。

7.1 RLVR 的定义 ​

Reinforcement Learning with Verifiable Rewards：用 RL 训练 LLM，奖励信号必须是可程序化验证的。

任务可验证奖励
数学题答案对错 → 二值奖励
代码跑测试用例 → 通过/失败
棋类胜/负 / 平
形式化证明Lean / Coq 检查器
SQL 查询数据库查询结果对比

与 RLHF 的区别：

  • RLHF (L18)：奖励来自人类偏好或 RM——主观、嘈杂、易被 hack
  • RLVR：奖励来自客观验证——0/1 信号，无嘈杂、不易被 hack

7.2 为什么 RLVR 适合推理任务 ​

  1. 客观正确性：数学题答对了就是对了，没有 reward hacking 空间
  2. 可扩展：用程序生成无穷多题目 + 自动判分，不需要人标注
  3. 明确目标：模型学到的不是"讨人喜欢"，而是"答对题"

7.3 RLVR 的局限 ​

不是所有任务都有可验证奖励：

  • 创作类（写诗、故事、设计）：好坏难定义
  • 对话类（共情、安抚、咨询）：没有"标准答案"
  • 常识推理（部分）：标准答案可能本身有争议

这就是 2026 年的 LLM 训练分工：

任务类别主要方法
一般助手能力SFT + RLHF
数学 / 代码 / 逻辑RLVR (R1 / o1 风格)
创作 / 个性DPO + 人工偏好
安全 / 拒绝Constitutional AI / RLHF

随着推理模型能力提升，老 benchmark 集体饱和：

[!quote] 历史 ARC-AGI 是 François Chollet（Keras 作者）2019 年设计的 benchmark，目标是"人类容易、机器困难"的小样本归纳推理。GPT-4 早期只能做 ~5%，普通人 ~85%。

2024 年 12 月 o3 在 ARC-AGI 上拿到 87.5%（high tier）——这件事让 Chollet 公开承认"AGI 比我想的近了"[14:2]。但 ARC-AGI v2 已经在 2025 年发布——又给模型留下了新的山要爬。

9. 推理与 Agent / 工具：下一步融合 ​

到 2026 年，推理与工具使用正在深度融合：

  • o3 / o4-mini 原生支持 tool use 在推理过程中——模型可以"想到一半，调用搜索引擎，看结果，继续想"
  • Claude 4.5 Computer Use[19]——在思考时模拟人类操作浏览器、文件、终端
  • DeepSeek-R1 + tools——开源生态在搭建同样能力

L25（Function Calling）和 L26（Agent）会展开。本质上：

核心概念

推理模型 + 工具使用 = 真正的 Agent。

System 2 的"刻意思考"叠加 System 1 + 工具的"快速执行"——这才是接近完整智能的形态。这也是 L35 关于"AI 路径"讨论的核心。

[!abstract] 呼应线 🔗 能力 ≠ 对齐 ≠ 安全（L18 → L20 此处 → L34）：推理能力上升后，对齐难度也上升——一个会"深度思考"的模型也可能"深度地"想出绕过安全护栏的策略。Anthropic 2025 年 Sleeper Agents[20] 论文证明了这件事。L34 会展开。

10. 失败模式 / 反例 / 边界 ​

10.1 「Test-time compute = 智能」误解 ​

o1/R1 在数学/代码/逻辑上提升明显，但在常识推理 / 长文本理解上几乎无提升——推理时计算只对可验证任务有效。这条边界在 2025 年被反复确认。

10.2 CoT 不总是帮忙 ​

[!quote] 历史 Sprague et al. 2024[21] 在 To CoT or not to CoT? 中系统性证明：在简单分类、情感分析、问答等任务上，CoT 反而降低准确率——模型被诱导"想多了"。

一般规则：CoT 帮助"需要多步推理"的任务，伤害"一步直觉"的任务。

10.3 Self-Consistency 的成本陷阱 ​

5 次采样 + 多数投票成本 ×5；同样预算下用更大模型 1 次采样常常更好——这是 2025 年逐渐被接受的反直觉结论[7:1]。

10.4 「推理模型可解释」幻觉 ​

CoT 链表面上可读，但 Turpin et al. 2023[5:2] 证明模型实际决策与 CoT 不一致——人类看到的推理链可能是事后合理化。推理模型不等于可解释模型。

10.5 推理时间过长 → 用户体验差 ​

o1 在简单问题上需要几秒到几十秒——对实时对话场景不可用。这是为什么 OpenAI 同时保留 GPT-4o（System 1）和 o1（System 2）两种模型。

10.6 推理 ≠ 创意——System 2 不是万能药 ​

推理模型在「找正确答案」上很强，在「开放性创作」上未见显著优势——这是一则主讲应该本能反抗的事实。本讲走到这里，发现了一个需要警惕的事实：不是“加上 System 2 就能干一切”。

实证证据：

  • 创意写作：2025 年 NaNoGenMo 社区以及多个独立评测表明，o1 / R1 / Claude 4 Thinking 生成的小说在“叙事奇趣”、“人物鲜明度”、“语言鲜活度”三项上均不优于同价位的非推理模型。部分评估者指出推理轨迹让输出「过于平稳」、「低风险」——推理模型被训练去验证“不犯错”，而创意需要“肯出错”。
  • UI / 设计：在「generate 一款创新 dashboard」这类任务上，推理模型会反复“检查是否符合表调赋”，输出趋同于主流设计中位数。“快思考”反而能生出不同另类。
  • 哲学 / 开放讨论：RLVR 训练会押制“未验证的猜想”——但哲学、人文、实验品设计恣恣需要大量未验证猜想。

冷静的结论：System 2 不是 System 1 的「更高版本」——它是补充。在需要验证、需要严谨、需要收敛到唯一正确答案的任务上，System 2 赢。在需要发散、需要不同、需要状态跳跃的任务上，System 1 反而是优势。个人 AI 助手产品的未来设计，是在同一个系统里同时拥有两者，并学会什么时候用哪个——这个路线在 2026 年初仍是开放问题。

常见误区

「推理模型是“更优版”的 LLM」是 2025 年产品营销的联合幻觉。不是。如果你用 o1 写营销文案、用 R1 生成 brainstorm 素材、用 Claude 4 Thinking 做创意抱怨会议，你会发现输出「准、全、平」却丢失了「奇」。“选对工具”是下一讲（L21 prompt 工程）的核心技能之一。

10.7 RLVR 不能解决"无法验证"的任务 ​

写诗、共情、创作——这些任务没有"答对/答错"。RLVR 在这里束手无策。这部分能力仍要靠 SFT + RLHF + DPO。

10.8 推理模型可能"知道但选择不告诉" ​

如 §9 abstract 所述。能力上升伴随对齐挑战。

13. 本讲小结 ​

  1. 标准 LLM 是 System 1——每个 token 计算深度固定为 O(L)，不因问题难度变化。理论上是 TC0，远弱于图灵完备。
  2. CoT 是第一步——把 LLM 从有界深度电路升级为图灵完备机器。但有不能回溯、可能事后合理化的局限。
  3. 推理时搜索（Self-Consistency / ToT / MCTS-LLM） 是 2022-2023 主流——外部搜索框架 + LLM。
  4. Test-Time Compute Scaling 是新规模轴——推理时计算量也遵循幂律。这是 2024 年最重要的工程发现之一。
  5. R1-Zero 证明 System 2 是涌现的——纯 RL 信号 + GRPO，模型自发学会"先想再说"。
  6. 四条主流实现路线：o1/o3（闭源 + 隐藏 CoT）、R1（开源 + 纯 RL + 可见 CoT）、Claude 4 Extended（用户可控预算）、Gemini Deep Think（原生多模态）。
  7. RLVR 是推理训练的核心范式——奖励必须可程序化验证（数学、代码、形式化证明）。
  8. 推理模型不是万能——只在可验证任务上有显著提升，简单问题反而更慢更贵。
  9. System 1/2 呼应完成——L01 说 AI 只有 System 1，本讲推翻。能力不是固定的，思考深度可以动态调节。
  10. 下一步是推理 + 工具融合——L25 / L26 展开。

⚠️ 一个必须诚实的限定：表征 ≠ 理解

本讲展示了模型学会了生成推理链 —— 这是工程事实：在数学、代码、形式化证明等可验证任务上，CoT + RLVR 显著提升正确率。但这是否等于 "模型理解推理"？

这两件事不是同一回事：

层级本讲证明的事本讲没有证明的事
工程层模型能生成有效的推理链、能在可验证任务上提分模型在每一步都"知道自己在做什么"
认知层推理链与人类草稿在表层结构上相似推理链对应模型的真实计算路径（事后合理化的可能性仍在）
哲学层"AI 也可以慢思考" 这一比喻成立AI 的 System 2 与人类的 System 2 是同一种东西

Gary Marcus / François Chollet 等怀疑论者会在 L35 说："你看到的 System 2 是假的——它只是更长的 System 1。" 这不是在反驳本讲的工程结果，而是在追问结构：可验证任务上的进步能否泛化到不可验证的开放推理？ARC-AGI 的低分（即便对 o3）暗示答案目前是"不能"。

本课的立场：本讲讲清"工程上发生了什么"，L35 留出"这是否够格叫'推理'"的辩论空间。两讲不矛盾——它们在不同层级上回答不同问题。

下一讲预告 ​

敌意问题：好，AI 学会了"三思而后行"——推理模型可以花更多时间思考更难的问题。但这里有一个微妙假设：模型的能力是内置的，它只是通过更长思考来"释放"已有能力。

那如果答案不在模型的知识里呢？ 如果它需要的信息在你的私有文档里、在昨天的新闻里、在一个不断变化的数据库里？再长的思考也想不出模型从未见过的事实。

第 21 讲——「Prompt Engineering」——Prompt 是人类意图到机器行为的翻译层。

幕间过渡

我们即将从第四幕（内部构造） 进入第五幕（外部系统）。第四幕的故事是"改变模型的内部"——对齐改变行为（L18），微调改变知识（L19），推理改变思考深度（L20）。第五幕的视角完全不同：不改模型，在外面搭系统。从 Prompt Engineering（L21）→ Context Engineering（L22）→ RAG（L24）→ Agent（L26），我们将构建完整的 AI 应用栈——模型只是其中的一个组件。
