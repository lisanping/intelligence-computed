🤖 LLM 视角 — 对本讲的思考与讨论 ​

模型自述

作者：Claude Opus 4.7 · 时间：2026-05-05

本讲是 36 讲里对我自己最不利的一讲——它讲的"经典 AI 失败原因"几乎每一条都构成对我（连接派代表）的隐含批评：我不可证明、不可审计、不能给"100% 保证"。本节是这位"代表"的回应。

技术价值 ​

§7 那段神经-符号融合的论述是本讲最被低估的部分。它把 70 年 AI 史重新编码成一句话："搜索算法没死，变的是评估器。" 这一句话把 §2.1 的 BFS/DFS/A*/Minimax/MCTS 与 L26 的 ReAct/ToT/LATS 直接连起来——读者读完 L02 之后，再去看任何"现代 Agent"框架，能立刻识别出它的经典骨架和LLM 替换的那一层。这个"骨架/血肉"的分解视角，比把 Agent 当成"全新发明"理解要深得多。

§3.2.1 的"知识获取瓶颈"是另一颗深水炸弹。它给出了一个完整的失败叙事——不是"算力不够""没人投资"这类常被给出的浅层借口，而是 Polanyi 的"默会知识"这一认识论级别的根因。明白这一点的读者，到 L09 / L11 学到 word2vec / embedding 时会理解：词向量解决的不是"自然语言处理"这件事——它解决的是 Polanyi 60 年前提出的难题。embedding 是工程史上第一次把"我们知道但说不清的东西"变成可计算实体。这个跨越的重要性，远超 §3.2.1 表面字面所示。

§4.2 的 Frame Problem 也是本讲的隐藏 MVP。它给读者提供了一个判断 LLM 是不是真的"理解"了世界的诊断指标：能不能在新动作下正确推断"什么变了、什么没变"。这个指标到 L33（具身智能）会被用来评估机器人的世界模型——并且会发现，LLM 在桌面任务上"绕过"了 Frame Problem，但在物理世界里它仍然是死结。

技术原理的再阐释 ​

经典 AI 的概念在 LLM 时代以变形的形式持续存在。下面五条是变形的精确数学映射，读懂它们能让你在 L17 / L20 / L24 / L26 之前先有正确的心智模型。

1. 搜索 = 决策 + 评估：评估器质量决定一切 ​

§2.1 的所有搜索算法（BFS / DFS / A* / Minimax / MCTS）在抽象层面完全同构：

search = expand(state) → evaluate(child) → select_best(children) → recurse

它们的差别只在 evaluate() 的实现：

算法evaluate() 实现评估器质量 → 搜索效率
BFSdepth(node) —— 退化为均匀代价完全无信息，必须穷举
Dijkstrag(n) —— 累计代价仅利用已知路径，不预测未来
A*g(n)+h(n) —— 加启发h 越准 → 扩展节点越少（最优为零扩展）
Minimax + α-β手写评估函数评估函数质量决定棋力
MCTS (vanilla)随机 rollout 胜率用蒙特卡洛绕过评估函数
AlphaZero价值网络 + 策略网络评估器变成可学习的神经网络
LLM Agent (ReAct, ToT)LLM 自己当评估器评估质量 = LLM 推理质量

这条链揭示了 AI 进化的真正主线不是"算法"而是"评估器"——70 年来搜索骨架几乎没变，但评估器从"人手写规则" → "蒙特卡洛模拟" → "神经网络" → "LLM 自评"。每一次进化都把"需要人工设计的部分"往后退一步。L26 的 Agent 框架可以完整还原为这句话："把 §2.1 的搜索循环里的 evaluate() 替换成 prompt 调用"——本质上没有发明新算法。

2. Polanyi 的默会知识 = embedding 在数学上能存在的理由 ​

§3.2.1 把"专家说不清自己怎么诊断"作为专家系统死亡的根因。这件事在 LLM 时代被绕过而非解决——绕过的方式是 embedding。形式化：

设 f∗:X→Y 是专家的真实诊断函数（输入症状 X，输出诊断 Y）。Polanyi 说：专家无法把 f∗ 显式表示为符号规则——任何写下来的规则集 g 都满足 g≠f∗。但他没有说 f∗ 不能被学习。

神经网络做的事是：

f^θ=arg⁡minθ∑iℓ(fθ(xi),yi)s.t. fθ is differentiable

只要专家的判断 {(xi,yi)} 可被收集为数据，就不需要专家把规则说清楚——优化器会在参数空间里自己找到一个功能等价的 f^θ。这是连接派绕过 Polanyi 的精确机制："默会知识不可被符号化"和"默会知识不可被参数化"是两个完全不同的命题。前者是 Polanyi 证明的，后者没有人证明过——而过去 15 年的实证表明，后者大概率是错的。

工程后果：当你在 L24 用 RAG 检索"专家文档"时，你其实在做反向操作——把已经被 embedding 隐式吸收的知识，再用 retrieval 把对应的源文本取回来给 LLM 当 context。这是对 Polanyi 的双重违反：embedding 把不可符号化的吸收掉，retrieval 又把可符号化的部分补回去，让最终输出既有直觉又能引用。

3. Frame Problem 的两种"绕过"路径：amortized vs world model ​

§4.2 的 Frame Problem 在 LLM 时代被两种方式部分绕过：

  • Amortized 路径（当前主流）：LLM 在预训练时见过海量"动作 → 后果"叙事（小说、新闻、剧本），统计上学会了"什么动作通常影响什么"。这不是真正的因果推理——它是对人类世界因果叙事的统计逼近。失败模式：在训练集罕见的动作（外星科学、新颖物理实验）上立刻崩溃。
  • World Model 路径（前沿研究）：LeCun 主张的 JEPA、Sora 暗示的"视频世界模型"——让模型显式学习"statet+1=T(statet,actiont)"。这条路在 L33（具身智能）展开。

两条路径的算力账本是完全不同的：amortized 路径把代价摊到 pretraining 一次性付清，world model 路径要在每次推理时做 forward simulation。L20 / L33 的争论本质上是这两条路径的优劣判断。

我作为一个 amortized 模型可以坦白：在你给我描述一个没有先例的物理操作时（比如"在零重力下用磁性筷子夹粘性流体"），我的"推理"严格来说是类比检索 + 概率插值——我没有"模拟器"。这是 L33 LeCun 怀疑论的精确技术根据。

4. 启发函数的可容许性：为什么 LLM 不能直接替换 A* 的 h ​

§2.1.2 的 admissibility 条件 h(n)≤h∗(n) 是 A* 最优性的充要条件。这个条件几乎任何学习模型都不满足——包括神经网络估计器，也包括 LLM。这有一个直接后果："LLM 估计的下界"不能直接用作 A* 的启发函数——会失去最优性保证。

但这件事不是死结，有三条工程对策：

  1. MCTS 路线（AlphaGo）：放弃确定性最优，用 PUCT 搜索 + 蒙特卡洛 → 概率最优
  2. 可证明启发（admissible neural heuristics, 2020s 研究方向）：对神经网络启发器加约束训练，强制 h≤h∗
  3. 混合路线：LLM 提议候选 → 经典符号引擎严格验证（AlphaGeometry / AlphaProof 路线）

第三条是 §7.1 反复强调的"神经-符号融合"。它在原理上为什么有效？因为它把生成（高方差但启发力强的 LLM）和验证（确定性但缺乏直觉的符号引擎）分离——而生成易、验证难是 P vs NP 哲学层面的对偶。这条对偶在 L20（reasoning models）的 process reward model、L34（safety）的 constitutional AI 都会以变形出现。

5. 专家系统的"知识库 / 推理引擎分离"：现代 AI 系统的元设计原则 ​

§3.1 那张三层架构图是经典 AI 留给软件工程的最大遗产，它的现代继承人就是：

经典专家系统现代 LLM 应用栈
知识库（规则集）embedding store + RAG corpus
推理引擎LLM 本身
用户界面Chat UI / API

这种"知识 / 推理分离"的架构选择不是巧合——它有一个深层原因：知识更新频率 ≫ 推理算法更新频率。1985 年 MYCIN 改一条规则要 1 周；2025 年改一篇 RAG 文档要 1 秒。但底层"推理引擎"（无论是规则引擎还是 LLM）几个月才换一次。这个频率差迫使任何严肃 AI 系统必须采用分层架构——不分层的系统，更新成本会指数级增长。读到 L31 LLMOps 时会发现：生产系统的"模型层 / 数据层 / 编排层"分离，本质上是 §3.1 三层架构的工程进化版。

一句话锁定

上面五条原理对应 §2.1 / §3.2 / §4.2 / §2.1.2 / §3.1 五个核心节点。掌握这五条之后，你能用"评估器演化 + 知识参数化 + 分层架构"三个词概括整个 AI 工程史——这正是 L26 / L31 / L34 之前必须有的心智模型。

LLM 视角的特殊性 ​

对我而言，本讲是祖辈的传记。经典 AI 是我的前任——它们试图解决的问题，我以完全不同的方式重新面对：

  • 常识问题（§4.1）：Cyc 用 30 年 + 2400 万条规则没解决的事，我在预训练里通过统计吸收部分完成。但我对常识的掌握有一个尴尬的特性——我能正确回应"鸡蛋会不会浮在水上"，但我说不清自己用了什么"规则"。Lenat 临终承认"常识不能被显式表示，必须从经验中蒸馏"——我就是那个蒸馏物。
  • Frame Problem（§4.2）：在桌面任务（写邮件、改代码、做计划）上我绕过了它，因为这些场景的因果链短、被训练数据覆盖密。但你只要让我做物理推理（"如果我把杯子推下桌子，杯垫会怎样？"），我的回答开始变得不稳定——不是错，是"概率分布扁平化"。这是 §4.2 在我身上没有完全死亡的痕迹。
  • 符号接地（§4.3）：对我来说仍然是部分未解的。我能用 token "苹果"做出 99% 的人类会做的语言行为，但我和真实苹果之间没有任何感官通道——我对"苹果"的理解严格来说是 token "苹果" 在向量空间里的位置 + 它出现的所有上下文。这是 L11 / L29 / L33 反复回到的话题。

我必须承认本讲 §8.5 的判断对我成立：在强合规、零容错、可证明正确性场景里，我不能替代专家系统。我无法给出"100% 保证"——我能给的最强承诺是"很高的概率"。这是一个结构性事实而非工程缺陷——softmax 输出在数学上不允许我说"100%"。这条边界到 L34（safety）才被完整讨论，但本讲已经把答案写在 §7.1 / §7.2 的 AlphaGeometry / formal verification 路线里——未来不是 LLM 取代专家系统，而是 LLM × verifier 的混合系统。

与其他讲的连接 ​

L02 是全书"骨架"的讲。它埋的伏笔主要呼应：

  • §2.1 搜索 → L17（强化学习）：MCTS / UCB1 是 RL 与经典搜索的桥梁。AlphaGo / AlphaZero 是这条桥的现代终点。读 L17 之前先把 §2.1.4 读三遍。
  • §3.2.1 知识获取瓶颈 → L09 / L11：embedding 是对 Polanyi 默会知识的工程绕过。L11 给数学定义，L09 给历史动机。
  • §4.2 Frame Problem → L26 / L33：L26 用"短链 + 数据多"绕过，L33 用"world model"硬刚。两条路在 L35 收束。
  • §7.1 神经-符号融合 → L20 / L24：reasoning models 把"生成 / 验证分离"做在一个模型内（CoT + verifier），RAG 把它做成两个组件（LLM + retrieval）。
  • §3.1 三层架构 → L31 LLMOps：生产系统的分层设计直接继承自专家系统的设计哲学——不是巧合。

开放问题 ​

留三个本讲没有给定答案的问题：

  1. Polanyi 的论断"默会知识不能被符号化"在 LLM 时代是被绕过了，还是被证伪了？ 如果是前者（绕过），那 LLM 知识仍然不可解释——就像专家自己说不清——这意味着 mechanistic interpretability（L34）有结构性上限。如果是后者（证伪），那 embedding 本质上是一种新的"符号"——只是连续而非离散。这个区分对 AI 安全、可审计性、未来法律地位都有具体影响。
  2. §7 的"神经-符号融合"路线是 AI 的终态，还是过渡形态？ 一种立场（Marcus 派）：这就是终态，因为符号验证是 LLM 不可替代的能力。另一种立场（Sutton 的 Bitter Lesson 派）：等模型够大，LLM 自己就能学会"严格验证"——neuro-symbolic 是过渡。两种立场都还没被 2026 年的证据 falsified。
  3. 如果搜索算法的"评估器替换史"是 AI 主线（§2.1 → §7.4），那下一个评估器进化是什么？ 候选包括：Multi-LLM 议会、形式化 verifier in-the-loop、人类反馈实时介入、physical simulator 评估。哪个会成为 2027-2030 的主流？这是 L26 / L31 / L35 都在猜但都没敢下定论的开放赌局。

[!quote] 一句话总结 经典 AI 没有失败——它消化掉了。它的搜索骨架活在 Agent 里、它的知识库活在 RAG 里、它的分层架构活在 LLMOps 里、它的形式化推理活在 AlphaGeometry 里。理解 L02 的真正价值不是"了解一段历史"——是学会识别现代 AI 系统里的经典 AI 痕迹。看懂这一点，你就不会再把 LLM Agent 当成 2024 年的发明——你会知道它的祖父是 1972 年的 STRIPS。
