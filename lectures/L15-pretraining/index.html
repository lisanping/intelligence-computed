第 15 讲 · 预训练全景 — 被低估的工程现实 ​

Scaling Law 告诉我们"投多少资源得多少能力"，但训练一个大模型的工程现实远比公式复杂——数据从哪来、算力怎么分、训崩了怎么办？

当人人都能跑推理（API 调用 / Llama 本地化），训练能力才是真正的护城河。这一讲拆解大模型工厂的内部——你会理解为什么训练 GPT-4 需要 25,000 张 A100、连续 90 天、$60-100M——以及为什么 DeepSeek-V3 能用 1/20 的成本做到接近水平。

这一讲是 L14 (Scaling Law 公式) 与 L16 (开源 / 量化) 之间的工程现实讲——Scaling Law 是物理定律，预训练工程是把定律变成可操作系统的工程。

前置知识核心产出建议用时
L12（Transformer）、L14（Scaling Law）① 理解预训练数据管线（爬取 → 清洗 → 去重 → 混合 → 退火） ② 掌握三种并行策略（DP / TP / PP）+ 3D 并行 ③ 理解 FlashAttention、混合精度、容错机制 ④ 理解 MoE（混合专家）成为默认 ⑤ 看 ZeRO / FSDP 的显存优化 ⑥ 用 DeepSeek-V3 案例理解"工程效率 vs 资源优势" ⑦ 看 2026 年的训练账单 ⑧ 拿到 L16 (开源 / 量化)、L17 (RL)、L31 (LLMOps) 的伏笔阅读 ~75 分钟 + 动手 ~25 分钟

从上一讲到这一讲 ​

第 14 讲问：GPT-4 到底是怎么训出来的？

Scaling Law 的公式很优美，但公式不会帮你训模型。25,000 张 A100 GPU、连续运行 90 天、电费 + 算力约 $100,000,000——然后训练崩了，你怎么办？

本讲拆解四个工程真相：数据从哪来、并行策略怎么选、基础设施怎么搭、成本怎么算。最后用 DeepSeek-V3 的案例展示：$5.5M vs $100M，工程智慧如何弥补资源差距。

1. 数据管线：从互联网到训练语料 ​

1.1 数据从哪来？ ​

训练大语言模型需要天量文本。LLaMA 3 用了 15T tokens，是 GPT-3（300B tokens）的 50 倍。数据来源的典型分布：

来源占比（以 LLaMA 3 为例）特点
Common Crawl（网页文本）~82%规模巨大但质量极低，需大量清洗
代码（GitHub）~5%训练结构化推理能力，不只是写代码
书籍~3%高质量长文本，利于学习长程依赖
学术论文（ArXiv）~2.5%科学知识的主要来源
百科（Wikipedia）~2.5%信息密度最高的事实性文本
其他（StackExchange、Reddit）~5%对话式、问答式文本

核心概念

不是所有数据生而平等。 Wikipedia 只占 2.5%，但它的"单位信息密度"可能是 Common Crawl 的 100 倍。数据混合策略（Data Mix） 决定模型的知识结构——配比比总量更重要。

1.2 数据清洗管线 ​

Common Crawl 的原始数据质量极低——广告、导航栏、Cookie 弹窗、SEO 垃圾、色情网站。90% 以上是不想要的。 清洗管线通常包括六步：

  1. URL 过滤：去掉已知垃圾站点、色情站点、恶意站点
  2. 语言检测：用 fastText 分类器保留目标语种
  3. HTML 解析：去掉标签、脚本、样式，只留正文
  4. 去重（Deduplication）：MinHash 近似去重，砍掉 30-50% 的重复内容
  5. 质量打分：用分类器判断文本是否为"高质量内容"
  6. 安全过滤：去除个人身份信息（PII）、有害内容、版权敏感内容

直觉

从 100TB 的原始 Common Crawl 数据中，最终可能只剩 3TB——97% 被丢弃。预训练数据工程的核心工作是"从垃圾堆里淘金"。

1.3 去重为什么重要？ ​

去重不是可选的优化——它直接影响模型质量。Lee 等人（2022）发现[1]：

  • 重复数据会让模型记住而非学习——在重复段落上 loss 很低但泛化差
  • 去重后模型在下游任务上的表现显著提升
  • 极端情况下，训练数据中的重复段落会被模型逐字背诵——这是隐私泄露和版权风险的来源

1.4 数据混合：配方比原料更重要 ​

有了干净数据后，下一个问题是怎么混合。这没有理论最优解，但有经验法则：

LLaMA 1 (2023)LLaMA 3 (2024)DeepSeek-V3 (2024)
总数据量1.4T tokens15T tokens14.8T tokens
代码占比~4.5%~5%加重
趋势—数据量暴涨 10 倍代码和数学数据比例提升

核心趋势：更多数据 + 更高的代码/数学比例 + 多阶段混合。后期训练阶段会提高高质量数据的采样比例（称为"退火（Annealing）"）。

2. 并行策略：一个模型放不下一张卡 ​

2.1 为什么需要并行？ ​

一个 70B 参数模型仅参数就需要 140 GB（FP16），一张 A100 80GB 装不下。加上梯度和优化器状态，总显存需求翻 4-6 倍。必须把模型拆到多张 GPU 上。

三种核心并行策略（Parallelism）：

2.2 数据并行（Data Parallelism, DP） ​

直觉

最简单的并行：每张 GPU 持有完整的模型副本，但处理不同的数据。所有 GPU 独立前向传播和反向传播，然后同步梯度取平均。

梯度final=1N∑i=1N梯度i
  • 优点：实现简单，线性加速
  • 缺点：每张卡要装完整模型——模型太大就放不下
  • 适用：模型能放进单卡，只是想加速训练

2.3 张量并行（Tensor Parallelism, TP） ​

直觉

把模型的每一层横向切开。比如一个 FFN 层的权重矩阵 W∈Rd×4d，切成 4 份分给 4 张 GPU。每张 GPU 算自己那一份，然后通信拼回来。

W=[W1|W2|W3|W4],Y=[XW1|XW2|XW3|XW4]
  • 优点：单层可以拆到多卡，突破单卡显存限制
  • 缺点：每一层都需要 GPU 之间通信（AllReduce），对互联带宽要求极高
  • 适用：同一台机器内的 GPU（NVLink 高带宽）

2.4 流水线并行（Pipeline Parallelism, PP） ​

直觉

把模型的不同层分给不同 GPU。GPU-1 装第 1-20 层，GPU-2 装第 21-40 层。数据像流水线一样从前到后流过。

  • 优点：跨机器通信量小（只传层间激活值）
  • 缺点：气泡（Bubble）——当 GPU-2 在算前向传播时，GPU-1 在等待；反向传播时反过来。流水线越短，气泡越大
  • 解法：把一个 mini-batch 切成多个 micro-batch，让多个 micro-batch 在流水线中重叠

2.5 3D 并行 ​

实际训练中，三种并行同时使用——称为 3D 并行（3D Parallelism）：

  • TP 在机器内部（NVLink 高带宽）
  • PP 在机器之间（InfiniBand）
  • DP 在所有副本之间

深入阅读

Megatron-LM（NVIDIA, 2020）[2] 是 3D 并行的工程范本。DeepSpeed ZeRO（Microsoft, 2020）[3] 用另一种思路——不复制完整优化器状态，而是在 GPU 之间分片存储——大幅降低显存需求。

3. 基础设施：让训练不崩 ​

3.1 FlashAttention ​

标准 Self-Attention 的复杂度是 O(n2)，但更大的瓶颈是显存带宽——注意力矩阵需要在 GPU 的 HBM（高带宽内存）和 SRAM（片上缓存）之间反复搬运。

FlashAttention（Dao et al., 2022）[4] 的核心洞察：不要物化完整的 n×n 注意力矩阵，改为分块（tiling）计算。通过精心安排内存访问模式，实现 2-4 倍速度提升，同时显存占用从 O(n2) 降到 O(n)。

核心概念

FlashAttention 不改变 Attention 的数学定义——输出完全相同。它是一个纯 IO 优化：减少 GPU 内存搬运次数。这提醒我们：在大规模训练中，算术复杂度不是唯一的瓶颈——内存带宽同样关键。

3.2 混合精度训练（Mixed Precision Training） ​

模型参数默认是 FP32（32 位浮点数），但训练中的大部分计算可以用 FP16 甚至 BF16（bfloat16）完成：

精度位数数值范围用途
FP3232大范围高精度主权重（master weights）、损失计算
FP1616小范围前向/反向传播
BF1616大范围低精度前向/反向传播（不需要 loss scaling）

混合精度训练的策略：用 BF16 做计算（快），用 FP32 存主权重（准）。显存减半，速度翻倍，精度几乎不损失。

3.3 容错：训练一定会崩 ​

常见误区

很多人以为大模型训练失败是"小概率事件"。事实正相反——在万卡集群上训练几个月，硬件故障是必然发生的。Meta 在训练 LLaMA 3 时报告了 419 次硬件中断[5]。

容错的核心机制：

  • 定期 checkpoint：每隔 N 步保存完整的模型状态（参数 + 优化器 + 学习率调度器 + 随机种子）
  • 自动恢复：检测到故障后自动从最近的 checkpoint 重启
  • 冗余设计：关键节点有备用 GPU，检测到故障后自动替换

[!abstract] 呼应线 🔗 物理账单（L14 → L15 核心）：第 14 讲说 Scaling Law 把 AI 变成了"花钱买能力"的工程问题。本讲展示了这张账单的细目：不只是 GPU 的购买/租赁成本，还有电费、冷却、网络互联、工程人力、以及训练崩溃导致的浪费。真正的"物理账单"比 Scaling Law 公式暗示的要大得多。

4. 成本对账：训练一次 GPT-4 要多少钱？ ​

4.1 成本阶梯 ​

模型估算训练成本训练硬件训练时长
GPT-3 (175B, 2020)~$4.6M~1,000 A100~34 天
LLaMA 2 (70B, 2023)~$2M2,048 A100~23 天
GPT-4 (2023)$60-100M（估）~25,000 A100~90 天
DeepSeek-V3 (671B MoE, 2024)$5.5M2,048 H800~60 天

核心概念

DeepSeek-V3 的成本只有 GPT-4 的 1/20，但在多项基准上达到了可比水平。这证明了一个关键论点：工程效率可以部分替代资源优势。便宜不是因为投机取巧，而是因为在数据、架构、训练策略上都做了更聪明的选择。

4.2 DeepSeek-V3 案例分析 ​

DeepSeek-V3 如何用 $5.5M 做到接近 GPT-4[6]？

  1. MoE 架构（Mixture of Experts，混合专家模型）：671B 总参数，但每个 token 只激活 37B——推理成本大幅降低
  2. Multi-Head Latent Attention（MLA）：压缩 KV 缓存，降低推理时的显存占用
  3. FP8 训练：比 BF16 再省一半显存和计算
  4. 高效数据配方：14.8T tokens，代码和数学数据比例较高
  5. 两阶段训练：先用大批量长训练预热，再用高质量数据退火

直觉

如果说 GPT-4 是"不计成本堆资源"，DeepSeek-V3 就是"在每个环节都精打细算"。前者证明了 Scaling Law 的上限，后者证明了工程智慧的下限——同样的能力可以用小得多的成本实现。

5. MoE：混合专家成为默认 ​

2024-2026 年所有前沿大模型几乎都是 MoE 架构。

5.1 MoE 的核心想法 ​

[!quote] 历史 MoE (Mixture of Experts) 思想可追溯到 1991 年 Jacobs et al.[7]。Shazeer et al. 2017[8] 把它带入深度学习。

2024 年 Mixtral 8×7B、DeepSeek-V3、Llama 4、GPT-4 (传闻)、Gemini 1.5+ 全部采用 MoE。

MoE 的设计：

  • 一层 FFN 替换为 E 个并行的 expert FFN（如 8 个、16 个、64 个、256 个）
  • 一个 router 决定每个 token 应该路由到哪 k 个 expert（通常 k=2）
  • 总参数量大（如 671B）但每 token 激活参数少（如 37B）

5.2 MoE 的优势 ​

维度DenseMoE
总参数NN×E/k（更大）
推理 FLOPs与 N 成正比与 N 成正比（同等推理成本）
训练 FLOPs与 N 成正比与 N 成正比
容量受限大很多——更多知识
训练难度低高（需要负载均衡、路由稳定）

5.3 MoE 的工程挑战 ​

  • 负载均衡：避免某些 expert 过载，其他闲置
  • 路由稳定：训练时路由分布快速变化会导致不稳定
  • 通信开销：跨设备 expert 通信开销大（all-to-all）
  • 推理服务：动态 batch 难以 saturate 所有 expert

核心概念

MoE 让 Scaling Law 多了一个杠杆——你可以把模型变得非常大（更多知识），但推理成本不变。这是 2024-2026 年所有前沿大模型必须 MoE 的根本原因。

6. 显存预算：钱花在哪里？ ​

训练一个 70B 参数模型的显存预算（混合精度训练）：

组件显存占用说明
模型参数（BF16）140 GB70×109×2 字节
梯度（BF16）140 GB与参数等大
优化器状态（FP32）560 GBAdam 需要 2 份矩 + 1 份 FP32 参数副本
激活值变量取决于 batch size 和序列长度
总计~840+ GB至少需要 11 张 A100-80GB

常见误区

显存的大头不是模型参数——是优化器状态。Adam 优化器为每个参数维护一阶矩和二阶矩估计，外加一份 FP32 主权重——总共需要模型参数 4 倍的显存。DeepSpeed ZeRO 的核心贡献就是把优化器状态分片到多张 GPU 上[3:1]。

失败模式 / 反例 ​

本节列出本讲核心结论不适用或易被误用的常见情境。教学的目的不是制造「已学会」的错觉，而是认清边界。

  • 「数据越多越好」反例：The Pile 中 ~10% 是低质量重复数据；DeepSeek/Qwen 实践证明严格去重 + 质量过滤 比单纯堆量提升更大。
  • Common Crawl 的污染：CC 中含大量 LLM 生成内容（自 2023 起占比快速上升），训练新模型时若不过滤会陷入「模型坍缩」（Shumailov 2024）。
  • Tokenizer 的隐藏偏见：GPT-2 BPE 对中文 1 字 ~2-3 token，对英文 1 词 ~1.3 token——同等 context window 下中文用户被「惩罚」。
  • 「续训」失败模式：在专业领域（医疗、法律）继续预训练常导致 catastrophic forgetting——通用能力崩塌。这是 L19 fine-tuning 的核心痛点。

本讲小结 ​

  1. 数据清洗是预训练中最被低估的环节——从 Common Crawl 的原始数据到可用语料，97% 被丢弃。
  2. 三种并行策略各司其职——DP 加速、TP 拆层、PP 拆阶段，3D 并行是实战标配。
  3. FlashAttention 和混合精度是性能倍增器——不改数学，只改 IO 和精度，换来 2-4 倍加速。
  4. 训练一定会崩——容错不是可选的——定期 checkpoint + 自动恢复是万卡训练的生命线。
  5. DeepSeek-V3 证明工程效率可以替代资源优势——$5.5M vs $100M，同等能力不需要同等投入。
