M3 · TinyGPT 训练 + 缩放实验 ​

对应：幕三（L12–L16） · 建议工作量：6–10 小时（GPU 优先） 核心命题：Transformer + Scaling Law 的可观察性；预测 = 压缩 = 优化。

项目目标 ​

在 tinyshakespeare 数据集上训练 3 种规模的 TinyGPT，亲眼看 Scaling Law：

  1. Tiny（~50k 参数）
  2. Small（~500k 参数）
  3. Base（~5M 参数）

输出 loss vs compute 双对数图，验证幂律。

必做项 ​

  • [ ] 复用课程 L12-transformer/src/demo/nanogpt_from_scratch.py 起步
  • [ ] 三种规模各训 ≥ 5000 step，记录 loss 曲线
  • [ ] 算出每种规模的总 FLOPs（用 6 * N * D 近似估计）
  • [ ] 出图：val_loss vs FLOPs 双对数；线性拟合验证幂律
  • [ ] 拟合幂律斜率，与 Kaplan 2020 对比
  • [ ] 写 200 字反思

scaffold 用法 ​

bash
cd assessments/milestones/M3-tinygpt-scaling/scaffold
pip install -r requirements.txt
python train_scaling.py --size tiny --steps 1000   # smoke (~3min CPU)
python train_scaling.py --size small --steps 5000  # ~30min on 1 GPU
python train_scaling.py --size base  --steps 5000  # ~2h on 1 GPU
python plot_scaling.py
pytest tests/

CPU 用户用 --steps 200 做 smoke；幂律可能不明显，但流程完整。

反思题 ​

  1. 你拟合出来的幂律指数，与 Kaplan 论文的 αN≈0.07 是否同量级？为什么会有差异？
  2. 训练曲线里有没有"涌现"现象（突变性能跃升）？如果有，是真涌现还是评估指标伪影？
  3. 把同样 FLOPs 用于"更大模型 + 更少 epoch" vs "更小模型 + 更多 epoch"，哪个赢？为什么（提示：Chinchilla）？
  4. 如果数据从 tinyshakespeare 换成 OpenWebText，你预期幂律斜率会怎样变？

通过线 ​

  • 及格线（60）：至少 4 个不同模型规模训练完成 + 拟合出幂律 → 进入下一幕
  • 优秀线（85）：幂律指数 α_N 在 [0.05, 0.10] 区间内（与 Kaplan 量级一致） → 可作为公开作品发表
  • 加分项（最多 +5 / 不超过 100）：加做 Chinchilla 风格的 compute-optimal 实验

参考实现要点（给评分人 / 卡壳学员） ​

⚠️ 不要直接拷贝。这是要点，完整代码请自行写。

  • 从 nanoGPT 修改：把 n_layer / n_head / n_embd 做 4–6 个等比缩放 (e.g. d=64,128,256,384,512)
  • 数据集用 tinyshakespeare (1 MB) 控制训练时间，每个规模训到 loss 曲线平稳
  • 用 scipy.optimize.curve_fit 拟合 loss = (N_c/N)^α + L0
  • 画 log-log 图最关键——线性才说明幂律成立
  • 典型陷阱：未控制 token 总数（不同规模训练步数等同会让小模型欠训练）
