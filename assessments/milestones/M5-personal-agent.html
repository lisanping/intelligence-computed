M5 · 个人 Agent 助手 ​

对应：幕五（L21–L31） · 建议工作量：8–12 小时 核心命题：外部构造的护城河——模型是商品，构造系统是差异化。

项目目标 ​

构建一个端到端 Agent，至少满足：

  1. 核心循环：PGE（Plan → Generate → Evaluate），可多步迭代
  2. RAG 子系统：把一个本地知识库（默认：用户自己的笔记/PDF）做嵌入 + 检索
  3. 至少 3 个工具：search、calculator、file_io（推荐再加 1 个 MCP 工具）
  4. 可观测性：记录每步 prompt / tool call / tokens / 成本
  5. 评估：至少 5 个测试用例自动化通过

必做项 ​

  • [ ] Agent 主循环（ReAct 或 PGE 风格皆可）
  • [ ] RAG 索引构建（chunk + embed + 存到本地 vectordb，推荐 Chroma/Qdrant）
  • [ ] 至少 3 个工具，含 schema 描述
  • [ ] Trace 日志：每个 turn 写一行 jsonl
  • [ ] 5 个评测用例 + 自动化判断
  • [ ] 写 300 字反思（Agent 失败模式 / 成本归因 / 改进方向）

验收标准 ​

#标准测试
1python agent.py --query "..." 能完成至少 2 步循环tests/test_agent.py::test_loop
2RAG 索引 + 检索可用tests/test_agent.py::test_rag
3至少 3 个工具被注册tests/test_agent.py::test_tools
4Trace 日志格式正确tests/test_agent.py::test_trace
55/5 测试用例通过率 ≥ 60%tests/test_agent.py::test_eval_suite

scaffold 用法 ​

bash
cd assessments/milestones/M5-personal-agent/scaffold
pip install -r requirements.txt
export OPENAI_API_KEY=...
python build_index.py --src ./my_notes/   # 一次性建索引
python agent.py --query "总结 my_notes 中关于 X 的要点"
python eval_suite.py                       # 跑 5 个评测用例
pytest tests/

反思题（300 字以上） ​

  1. 你的 Agent 在哪几个环节最容易失败？是 plan 错、tool call 错、还是 evaluate 错？
  2. RAG 召回质量与 Agent 回答质量是不是线性相关？观察到了什么反例？
  3. 5 个评测用例里，哪几个是"显然能通过"，哪几个揭示了系统盲区？
  4. 如果给你 $1000 把这个 Agent 推到生产，钱会花在哪 3 处（提示：L31 LLMOps）？
  5. 课程命题"模型是商品，构造是护城河"——你做完这个项目后是更同意还是更怀疑？

详细评分 rubric（满分 100） ​

通用 4 维（功能 30 / 测试 30 / 反思 25 / 代码 15）在本项目细化为：

维度满分1–5 分（不及格）6–8 分（合格）9–10 分（优秀）
功能完整性 (30)PGE 闭环 + RAG + 至少 3 个工具PGE 缺失 / 只能单步PGE 闭环 + RAG + 3 工具 + eval_suite 跑通+ MCP Server 化 / 多 Agent 协作 / 失败自动重试
验收测试 (30)6 项自动化测试全过通过 ≤ 3 项通过 4–5 项全过 + 自加端到端集成测试
反思与判断 (25)5 道反思题（300+ 字）< 300 字 / 只列功能300+ 字 + 失败模式归类（plan/ground/eval 三象限）500+ 字 + 生产成本分解 + 立场转变陈述（命题 C 是否被验证）
代码质量 (15)模块化 + 可观测单文件 / 无日志模块化 + 结构化日志 + seed=1337+ trace 可视化 + token 成本统计 + 自动评估流水线

通过线 ​

  • 及格线（60）：5 个评测用例中 ≥ 3 个端到端通过 → 进入下一幕
  • 优秀线（85）：完整 PGE 闭环 + 至少 1 次失败后自我纠错 → 可作为公开作品发表
  • 加分项（最多 +5 / 不超过 100）：把 Agent 部署成 MCP Server 供其他工具调用

验收 checklist（提交前自查） ​

  • [ ] python agent.py 一键完成，无未捕获异常
  • [ ] pytest tests/ 全过（6/6）
  • [ ] 输出文件齐全（results / figures / reflection 等）
  • [ ] 所有随机种子统一为 1337（如适用）
  • [ ] git status 干净，提交时附 commit message：milestone: M5 完成 — pass=X/5

参考实现要点（给评分人 / 卡壳学员） ​

⚠️ 不要直接拷贝。这是要点，完整代码请自行写。

  • 推荐数据：你自己的 Obsidian / Notion / 笔记目录（500–5000 文档）
  • Embedding：sentence-transformers/all-MiniLM-L6-v2 或 bge-small-zh
  • 向量库：chromadb 本地模式（无需服务器）
  • Agent 框架：可用 LangGraph / OpenAI Agents SDK / 自实现 PGE 循环
  • 工具集合：① 检索本地笔记 ② 调用 LLM 总结 ③ 写入新笔记（带人工确认）
  • 典型陷阱：让 Agent 自动写文件而无人工确认 → 直接破坏 PGE 中的 Evaluate 关
