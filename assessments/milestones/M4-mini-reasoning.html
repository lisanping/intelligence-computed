M4 · 推理模型微缩复现 ​

对应：幕四（L17–L20） · 建议工作量：5–7 小时 核心命题：内部构造（对齐 / 微调 / 推理时计算）能让小模型超出"裸预训练"的表现。

项目目标 ​

在 GSM8K 数学题子集（200 题）上，对比 4 种推理策略的准确率：

  1. Zero-shot 直答（baseline）
  2. Chain-of-Thought（"Let's think step by step"）
  3. Self-Consistency（CoT + 多次采样取多数）
  4. Test-Time Compute Scaling（用现成推理模型 API 如 DeepSeek-R1 / o3-mini 对比）

输出准确率 vs 平均 token 成本散点图，亲眼看 System 1 → System 2 的代价/收益。

必做项 ​

  • [ ] 4 种策略全部跑通，每题输出预测 + 推理链 + token 数
  • [ ] 准确率统计，绘制 acc vs avg_tokens 散点图
  • [ ] 至少使用 1 个开源 LLM（OpenAI / Anthropic / DeepSeek API 二选一即可）
  • [ ] 写 200 字反思

可选：如果完全离线，可用本地 Qwen2.5-7B-Instruct + Ollama 跑 baseline；推理模型部分用 DeepSeek-R1-Distill-Qwen-7B。

验收标准 ​

#标准测试
1python run_strategies.py --strategy zero 成功tests/test_strategies.py::test_zero
2输出 results_<strategy>.csv 含 pred / correct / tokens 列tests/test_strategies.py::test_schema
3任一策略 accuracy ≥ 0.30（GSM8K 难度 baseline）tests/test_strategies.py::test_baseline_acc
4figures/acc_vs_cost.png 生成tests/test_strategies.py::test_figure
5reflection.md ≥ 200 字manual

scaffold 用法 ​

bash
cd assessments/milestones/M4-mini-reasoning/scaffold
pip install -r requirements.txt
export OPENAI_API_KEY=...        # 或 DEEPSEEK_API_KEY / ANTHROPIC_API_KEY
python run_strategies.py --strategy zero --n 50
python run_strategies.py --strategy cot --n 50
python run_strategies.py --strategy sc  --n 50 --samples 5
python plot_results.py
pytest tests/

--n 控制题数（建议先 20 跑通，再 200 出图）。

反思题 ​

  1. CoT 对你选的模型提升了多少？用同样 token 数做 self-consistency 是否更划算？
  2. Self-Consistency 的"多数投票"在哪些题上失效？为什么？
  3. 推理模型（R1/o3）vs CoT-prompted base，哪个性价比更高？请给出一个具体决策建议。
  4. 这次实验的"Evaluator"（标准答案对比）足够可靠吗？换成 LLM-as-Judge 会怎样？（提示：L31）

详细评分 rubric（满分 100） ​

通用 4 维（功能 30 / 测试 30 / 反思 25 / 代码 15）在本项目细化为：

维度满分1–5 分（不及格）6–8 分（合格）9–10 分（优秀）
功能完整性 (30)4 种策略 × 1 个 benchmark只跑 ≤ 2 策略4 策略全跑 + 输出 results.csv + 对比图4 策略 + R1 推理模型加分项 + 多 benchmark 交叉
验收测试 (30)5 项自动化测试全过通过 ≤ 2 项通过 3–4 项全过 + 自加答案解析鲁棒性测试
反思与判断 (25)4 道反思题< 200 字 / 仅汇报准确率200+ 字 + token 成本 vs 收益分析300+ 字 + 失败案例分析 + LLM-as-Judge 替代讨论
代码质量 (15)可复现 + 答案解析健壮正则硬编码 / 错答识别为对答案解析有 fallback + seed 记录+ 缓存中间结果 + 失败案例自动 dump

通过线 ​

  • 及格线（60）：CoT 在选定 benchmark 上比 base 提升 ≥ 5 个百分点 → 进入下一幕
  • 优秀线（85）：self-consistency 在 ≥ 1 个题型上超越 CoT 单次 → 可作为公开作品发表
  • 加分项（最多 +5 / 不超过 100）：加测 R1-distill-Qwen-7B 推理模型作为第 4 方法

参考实现要点（给评分人 / 卡壳学员） ​

⚠️ 不要直接拷贝。这是要点，完整代码请自行写。

  • 推荐 benchmark：GSM8K (50 题子集) / MATH-500 (50 题) / ARC-Easy (100 题)
  • 基线模型用本地可跑的 7B–14B（Qwen2.5 / Llama3.1 / Mistral），通过 ollama 或 vllm
  • Self-Consistency：temperature=0.7 跑 5 次取多数投票
  • 推理模型用 deepseek-r1-distill-qwen-7b 或 o1-mini API
  • 典型陷阱：评分时用字符串完全匹配会漏掉 "the answer is 42." 这种格式——必须先解析答案
